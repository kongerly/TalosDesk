实施日期：2026-10-21。状态：**Core、schema 5、导入预览与 WPF 状态/占用/退出已接入并完成隔离自动化检查；未生成候选包**。源码应用版本暂保留 v0.3.0，新增能力尚未发布；配置版本独立升级到 5。以下保留完整契约及分批证据，第一批的 schema 4/桌面待接入描述仅为当时记录。

## 建议结论与取舍

首版采用“默认关闭、独立服务、非零退出、每轮最多追加 3 次”的策略。退避依次为 2、4、8 秒，单次上限 8 秒；成功启动、持续运行或 TCP 探测通过均不返还次数。只有用户再次明确运行或重启，才建立新一轮预算。

| 选择 | 评估结果 |
| --- | --- |
| 每轮固定 3 次，2/4/8 秒退避 | 建议采用。一次手动启动最多产生 4 个进程会话，快速失败后能自行停止；参数固定，便于解释和验证 |
| 稳定运行一段时间后自动清零 | 首版不采用。反复运行到阈值再失败会获得无限新预算，不符合本轮“有限”的边界 |
| 服务任何退出都重启，包括退出码 0 | 首版不采用。保留成功退出即结束的现有含义；代价是服务以 0 自行退出时不能自动恢复 |
| 分组内也自动恢复 | 后续单独评估。现有分组按单次失败立即清理其启动成员，自动恢复会改变这一契约 |
| 自定义次数、退避、随机抖动、按错误码分类 | 首版不增加。先交付单一开关和确定的边界，不建立通用守护进程或重试策略框架 |

这些数字是首版产品策略，并非性能测量结论；后续若依据使用反馈调整，应同步文案、预算和竞争条件测试。

## 适用范围与触发条件

“独立运行”按**本次启动来源**判断：单条运行、勾选多条批量运行中的每条服务均可生效。命令是否被某个分组引用不影响独立启动。由同时分组启动的会话一律不启用自动重启；顺序分组继续仅接受任务。编辑器、分组页和导入预览须说明“仅独立运行生效，分组运行不生效”。

只有以下条件全部满足，才安排下一次自动尝试：

1. 当前轮由用户明确启动，来源为独立运行，命令类型为服务，且配置开关为开启。
2. 当前会话的 `Completion` 成功返回 `CommandRunState.Failed` 和非零退出码；没有手动停止、重启替换、分组清理或确认退出等取消意图。
3. 本会话的归属 Job 内进程已全部退出，输出排空及会话资源收尾已完成；旧会话和本轮身份仍匹配，当前没有同命令的新会话。
4. 已实际发起的自动尝试少于 3 次，工作区可用，应用没有关闭启动入口。

任务命令、服务退出码 0、TCP 超时或不可达、stderr 内容、内存占用、日志写入失败均不触发重启。监听端口也不作为归属或退出依据。应用启动、读取、导入、窗口恢复和再次唤醒均不运行已保存命令。

初次手动启动的配置预检或进程创建失败时，不建立自动重试轮次。自动尝试也重新校验配置、工作目录和敏感变量；预检或进程创建失败立即结束本轮，显示失败类别，剩余次数不再执行。PowerShell 已成功创建、随后因脚本错误非零退出，则按上述普通失败条件处理，不推断错误是否可恢复。`Completion` 抛异常、无法确认归属进程退出时同样结束自动恢复，不盲目创建第二个会话。

**观察任务结束不等于归属已清空。**若观察抛错，或创建失败后无法确认已创建进程的清理结果，须保留“归属未确认”的故障占用及必要控制资源；在旧归属退出得到确认前，手动运行、手动重启、批量及分组也不得启动该命令。仍有控制资源时允许再次停止，无法确认时明确提示保留故障状态并退出应用处理，不能仅因 `Completion.IsCompleted` 释放占用或按进程名清理。

## 次数、退避与计数重置

一轮从一次成功的手动运行或手动重启开始，到正常退出、取消、恢复中止或次数耗尽为止。计数是本轮**已经提交的自动启动尝试数**，不是退出次数，也不包含最初的手动启动。

| 步骤 | 已提交自动尝试数 | 下一步 |
| --- | --- | --- |
| 手动启动成功后非零退出 | 0 | 等待 2 秒，准备第 1/3 次 |
| 第 1 次自动启动成功后非零退出 | 1 | 等待 4 秒，准备第 2/3 次 |
| 第 2 次自动启动成功后非零退出 | 2 | 等待 8 秒，准备第 3/3 次 |
| 第 3 次自动启动成功后非零退出 | 3 | 重试耗尽，不再排队 |

第 n 次等待为 `min(2 × 2^(n−1), 8)` 秒，n 只取 1、2、3。三次退避预算合计 14 秒；这是配置的等待时长之和，不是整体恢复的完成期限。服务每次运行时间、进程创建、输出排空、日志收尾与调度延迟均另计，不对总耗时作上限承诺。

- 在上一会话 `Completion` 返回并尝试完成其日志批次后才开始退避；磁盘日志收尾失败显示警告，但不将进程结果改为失败，也不单独触发或阻止既定重试。
- 采用可替换的 `TimeProvider` 和单调计时，不依赖系统墙钟；每个命令最多一个等待任务。延迟调度或系统恢复后只重新核对并执行当前待重试项，不补发多个“错过”的尝试。
- 等待不占用次数；到期后通过最终资格校验，在与停止/退出互斥的启动提交点将次数加一，再调用既有进程创建入口。创建失败消耗该次尝试并结束本轮；预检失败则不增加次数，但同样结束本轮。
- 自动启动成功、长时间运行、TCP 首次通过或恢复通过，都不清零。第 3 次自动启动即使稳定运行很久，后来非零退出仍算耗尽。
- 手动停止结束本轮并保留已用次数供当前界面解释；再次明确运行或重启成功后建立新身份、计数归零。等待中重复“运行”不重置计数、不抢占等待；“重启”可取消等待并立即走一次新的手动启动。
- 取消旧轮次发生在手动重启预检之前；若预检或停止失败，旧重试也不恢复。只有旧归属进程已确认结束且新手动启动成功后才获得新预算。重复点击重启合并，不创建多个新轮次。
- 开关是持久配置，次数、倒计时、取消原因和轮次身份仅在内存中。退出后不恢复等待，重新打开应用不自动运行；导出或导入不携带待执行重试。

## 停止、重启、退出与分组的优先级

优先级为：**确认退出/生命周期取消 → 手动停止或分组归属清理 → 手动重启替换旧轮次 → 自动重试**。取消针对明确的轮次及会话身份，不按命令名称或当前命令 ID 查找后任意停止新会话。

| 操作或事件 | 取消与后续行为 |
| --- | --- |
| 运行中手动停止 | 先记录取消意图、使本轮回调失效并取消等待，再对当前归属会话调用 `StopAsync`。即使同时收到了非零退出结果，也不重试 |
| 退避中手动停止 | 没有进程也必须接受，立即取消等待，显示“已取消自动重启”；已结束批次仍保留真实失败结果，不改写为“已停止” |
| 自动启动正在提交时停止 | 停止与提交使用同一串行入口。停止先取得入口则不得创建；若创建先完成，则登记并交付该确切会话后由停止流程结束它，不得漏管或再补一次 |
| 停止失败或取消了停止等待 | 自动重试仍保持取消，显示“停止未完成”，保留归属以允许再次停止。不能据此自动恢复，也不能启动重复进程 |
| 手动重启 | 先取消旧轮次，完成预检及旧会话停止/收尾，再创建新手动会话；成功后建立新预算。退出或后续停止已生效时，不执行尚未提交的新启动 |
| 分组取消或同组失败清理 | 只作用于该次分组确实启动且身份仍匹配的会话。首版这些会话从未启用自动重启，清理后也不得由共享回调补建轮次 |
| 分组遇到独立运行或正在退避的同一命令 | 视为已占用并跳过，不接管其轮次；分组失败清理不得取消被跳过的独立服务及其等待 |
| 关闭确认显示期间 | 暂停新的自动启动提交，但不停止正在运行的进程、不取消轮次、不消费次数。对话框的嵌套消息循环也不能让到期重试越过此门 |
| 选择“返回应用” | 解除上述临时暂停，保留原截止时刻和次数；已到期则重新校验后只发起一次，未到期则等待剩余时间 |
| 确认“停止并退出” | 在第一次异步等待前关闭全部启动入口、使所有轮次失效并取消定时等待，再取消顺序队列、停止本实例归属会话并收尾日志。只剩重试等待时也须显示确认并允许返回应用 |
| 确认退出后某会话停止失败 | 保留窗口及归属供重试停止；已取消的自动重试和待执行手动重启不自动恢复。只有用户再次明确运行/重启才可建立新轮次 |
| 最小化到托盘、切页、切换项目、窗口恢复 | 本身不取消重试。托盘“退出”复用同一关闭流程 |
| 工作区外部修改、重载、替换或移除相关配置 | 在应用替换配置前取消相关轮次；外部变更禁用保存/启动时同步取消等待，已运行进程保留既有停止入口。不能用旧配置继续自动启动 |
| 应用异常终止或系统关机 | 不保存或恢复重试队列；沿用现有 Job 归属清理边界，不承诺执行完整的正常退出流程 |

关闭流程先建立提交暂停，再读取确认所需的运行/待重试快照；已退出但恢复回调尚未处理的非终结轮次也计入待重试。无活动会话的快速退出路径同样必须关闭启动入口并取消全部轮次，不能让排队中的完成回调在退出检查后创建进程。所有关闭后的回调只可结束自身收尾，不可写入已关闭窗口。

确认退出不能等待 2/4/8 秒退避到期，也不能因为“正在自动重启”拒绝退出；仅等待已经提交的归属进程停止与既有日志收尾。取消重试不改变现有 Ctrl+C 等待 5 秒、必要时终止 Job 后再确认退出的规则，不按进程名批量终止，也不接管占用端口的其他程序。

## 状态、占用与日志

自动恢复状态独立于 `CommandRunState` 和 `TcpProbeState`；每次会话仍产生一次真实结果，不能把多个进程拼成一个永不完成的 `Completion`。

| 当前情况 | 建议界面与按钮行为 |
| --- | --- |
| 非零退出后等待 | “失败 · 退出码 X；Y 秒后自动重启（第 n/3 次）”；运行禁用，停止与重启可用 |
| 自动尝试正在提交 | “正在自动重启（第 n/3 次）”；重复运行/重启不提交，停止及退出意图仍可生效 |
| 自动会话已运行 | 保留现有进程/TCP 状态，附“自动重启已用 n/3 次”；探测从新周期重新开始 |
| 第 3 次运行再次失败 | “失败 · 自动重启已耗尽（3/3）”；无倒计时，停止禁用，运行/重启可建立新轮次 |
| 等待被取消 | “已取消自动重启（已用 n/3 次）”，另保留最后退出码与失败批次；无进程时可编辑或再次运行 |
| 预检或创建失败，且确认没有残留归属进程 | “自动重启已中止 · 固定错误类别（已用 n/3 次）”；不显示尚未执行次数为耗尽，修复后由用户运行 |
| 观察或清理异常，归属退出尚未确认 | “自动重启已中止 · 归属未确认”；保留故障占用，运行/重启禁用，仍有控制资源时允许再次停止 |

等待和提交中都属于“命令已占用”，参与防重复启动、批量过滤、分组跳过、相关命令/项目编辑与删除保护、工作区导入与重载保护、日志位置迁移保护以及退出确认；这些检查必须覆盖“无活动会话但有待重试”的状态。项目“运行中”和“TCP 探测通过”只统计实际活动会话，等待不计入运行或就绪；另显示待重试数量，避免把失败服务显示成正常运行。查看、复制和导出仍可用。

每次成功创建的会话使用新的运行版本、批次 ID、Job 和探测周期；启动失败不留下虚假的运行批次。等待期间保留刚结束会话的输出；新会话提交成功后再按现有规则切换到新批次。状态文案不插入 stdout/stderr、不改写旧退出码，历史批次不套用当前恢复或探测状态。本轮不新增历史日志字段；自动恢复的计数/原因仅供本次应用会话查看，跨应用启动的恢复链追溯暂不提供。

协调入口以命令 ID 串行化“校验轮次 → 确认无取消/关闭 → 消费预算 → 创建并登记会话”。停止/退出与启动共享这一边界；计时取消令牌只负责唤醒等待，不能单独代替身份与关闭状态校验。每次退出、计时和 UI 回调至少核对命令 ID、轮次代次及会话/运行版本，旧轮次不能删除、停止或覆盖新轮次。每个命令最多一条恢复链、一个待执行定时器和一个未完成会话。

配置已升级至 schema 5，只增加服务命令的 `AutoRestartEnabled` 布尔开关：缺省为 false，保存 false 时省略；null、非布尔、重复与未知字段拒绝，任务上 true 拒绝。schema 1–4 读取默认关闭且不改写文件，旧 schema 携带新字段即拒绝，下次成功保存才升级；旧应用应拒绝 schema 5。迁移时继续接受 schema 4/5 的合法 `TcpProbe`，schema 1–3 的非空探测仍拒绝。

编辑、复制、导出、导入合并须完整保留开关；切换任务时明确移除启用项，取消或保存失败保留原配置。导入预览展示开关和固定 3 次/2、4、8 秒策略及“分组不生效”，冲突替换沿用导入命令整套配置、保留本机则保留本机开关；导入不解锁执行、不启动重试、不建立连接。敏感变量继续每次按既有规则预检/注入，不把解密值写入恢复状态或诊断。

## 完整验收矩阵（Core 与桌面证据见下方，候选包未验收）

先用可控时钟、可阻塞的启动/完成替身验证核心时序，再在独立临时目录用合成 PowerShell 命令及隔离配置验证真实归属进程；桌面和候选包验收随后进行。竞争测试使用明确的屏障控制顺序，不依赖随机睡眠碰运气，不读取正式工作区。

## 第一批 Core 实施与实际检查

Core 入口为 `CommandRecoveryCoordinator`。`CommandStartRequest` 显式指定 `Independent` / `Group` 来源，策略参数默认 false，未进入工作区 JSON。宿主提供 `Prepare`：每次重新检查当前配置、目录及敏感变量，并返回本次 `CommandStartPlan`；Core 不缓存计划或解密值。预检在提交锁外执行，最终身份、取消、关闭和暂停校验、消费次数、创建与登记在同一串行入口完成。停止先取得入口则不创建；创建先取得入口则停止所登记的确切会话。新手动创建成功后才换轮次并清零预算，失败保留上一轮计数供解释。

`GetSnapshot` / `GetSnapshots` / `IsBusy` 提供轮次 ID、会话版本、真实会话、最后结果、单调倒计时、次数与固定错误类别。等待不伪装成活动进程。日志收尾通过 `FinalizeSession` 逐次调用，异常仅记录警告，仍根据真实退出结果决定恢复。旧会话的日志仍可收尾，但旧回调不能覆盖新轮次；分组清理使用带 `expectedSession` 的停止入口。

退出宿主先取得 `PauseAutomaticStarts`，再读快照和显示确认；返回应用时释放令牌，按原截止时间继续。确认退出调用 `CloseAndStopAsync`，调用返回任务前就关闭全部启动入口、取消所有轮次；只等待已提交会话及既有日志，不等退避或未提交的预检。停止失败保留归属，仍可再次停止。保留窗口时宿主可显式 `ReopenForManualStarts`，旧轮次仍保持取消，新的手动请求还须通过故障占用检查。替换或外部配置变化前用 `CancelRecovery` 取消相关恢复；宿主的配置可用性和编辑保护仍待下一批连接。

归属检查独立于 Completion 是否完成。观察失败保留 Job/进程句柄和停止能力；创建回滚也确认根进程及 Job，不能确认时以 `CommandCreationException.Ownership` 交付控制资源并由 Runner 保留占用。不会按进程名或端口清理。正常会话仍产生各自的 Completion，没有将恢复链包装成单个永不完成的会话。

## 第二批配置与桌面实施及实际检查

`Prepare` 在后台执行，仅在 Dispatcher 上复制确切项目/命令和工作区摘要，后台重新检查目录、摘要与敏感变量；未把明文放入恢复状态或诊断。写配置期间暂停自动提交，保存结束按原截止时间继续，自己的保存不会误判为外部变更。发现外部改写取消所有旧轮次并禁用新启动；替换、编辑或移除相关配置前取消相关恢复。启动后延迟补查只在从未发起过运行时重载，避免清掉快速运行产生的结果。

Core 增加成功创建后的 `SessionCreated` 登记回调，回调失败保留已创建会话与停止能力并记日志警告；自动预检阶段明确显示提交中。宿主仅在成功创建后建立批次，创建前短暂缓冲输出；每次会话以独立版本登记、切换批次和附加 TCP 回调。完成本次日志后才开始退避，磁盘失败保持警告，旧结果和历史状态不改写。故障 Completion 的批次记中断，归属继续由 Core 保留。

退出先暂停再读快照并显示运行/待重试或提交/顺序队列数量；嵌套消息循环内不自动提交。返回应用保留截止时间及预算；确认退出在第一次等待前关闭所有启动入口、取消全部轮次，再取消队列并停止确切归属。无进程快速路径同样关闭入口；停止失败保留窗口和再次停止，不恢复旧自动等待或手动重启。托盘退出沿用同一流程。
