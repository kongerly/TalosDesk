# schema 6 升级与回退指南

本文适用于包含 Windows Cmd 的新功能构建。当前本地构建尚未重新分配正式版本；先根据[发布说明草稿](release-next-draft.md)确认交付线，不要只凭 `rc.1` 文件名判断配置兼容性。

## 先确认格式

| 程序/交付线 | 能读取的 schema | 成功保存后 | 限制 |
| --- | --- | --- | --- |
| v0.3.0 或 schema 4 维护包 | 1–4 | 4 | 不能读取 5/6，不含自动重启、搜索、Cmd |
| 此前 schema 5 rc.1 构建 | 1–5 | 5 | 不能读取 6；与当前同名开发包不同 |
| 当前 schema 6 新功能构建 | 1–6 | 6 | 新增 Shell，缺省/0 为 PowerShell，1 为 Cmd |

只读取旧工作区不会升级；编辑、确认导入等导致的下一次成功保存会升级，即使全部命令仍使用 PowerShell。旧应用拒绝新 schema，不会自动降级。不要手改 `SchemaVersion` 或删除 Shell/恢复字段来绕过校验，这会丢失语义，也不构成可支持的回退。

更新提示只比较版本和渠道，不检查配置格式。未来 schema 4 维护版即使版本号高于本地 rc.1，也不能读取已升级的 schema 5/6；使用这类开发配置时，应继续选择支持其格式的新功能包，或使用兼容备份回退。

## 升级步骤

1. 确认新包来源、交付线、包内版本/渠道和 SHA-256。把 ZIP 完整解压到新的应用目录，不覆盖旧程序或混用两包 DLL。
2. 停止命令和待重试轮次，退出旧应用，确认本次归属进程已结束。记录界面显示的实际工作区路径；默认是 `%LOCALAPPDATA%\TalosDesk\workspace.json`，使用 `--workspace` 时以指定路径为准。
3. 完整复制工作区文件，记录其 schema，并备份需要保留的旁文件和日志。清单见[隐私说明](privacy.md#本机数据)：窗口状态、更新偏好/缓存、诊断设置/记录、日志位置记录及实际日志目录。自定义日志可能在工作区目录之外，也要单独复制。备份不应放进源码仓库或公开附件。
4. 保留旧版兼容备份不动，另复制一份用于试用。若需隔离试用日志，不要让副本的日志位置记录继续指向日常目录：保留备份记录，但试用副本不带该记录，使用默认的独立日志位置。其余旁文件按需复制，不必借用日常数据。
5. 在同一 Windows 用户下，用新应用和明确的副本路径打开，例如 `TalosDesk.App.exe --workspace "C:\Example\TalosDesk-Trial\workspace.json" --profile-label "升级试用"`。这是占位路径，应替换为自己的独立目录。检查项目、命令、分组、变量、TCP 与恢复开关；导入配置时先检查预览，确认后仍不自动运行。
6. 成功保存后核对 JSON 顶层 `SchemaVersion` 为 6。仅手动运行自己确认的合成命令，验证 PowerShell/Cmd、停止和历史读取；试用成功后，再按同样的停止、退出和备份流程切换日常工作区。不要让两个版本同时写同一文件。

完整备份保留 DPAPI 密文，但 `CurrentUser` 保护并不保证换账户或换机器可解密。可分享导出把敏感值改为待填写，不能代替完整备份。不要把备份或日志发给他人排障。

## 回退步骤

1. 在新版中停止命令、取消待重试并退出，确认归属已释放。把当前 schema 6 工作区和日志另行备份，保留升级后新增配置与历史。
2. 选择符合运行时安全基线、且支持备份 schema 的旧功能包。schema 4 维护包只接收 1–4 的备份；此前 schema 5 rc.1 只接收 1–5，不能直接打开当前文件。历史 10.0.12 包不应作为分发回退方案。
3. 从升级前备份复制工作区到独立的回退目录；需要恢复日志时配套恢复对应旁文件和日志副本，检查日志位置记录，避免指向仍需保留的新版目录。先核对 JSON schema，再用旧应用显式指定该副本启动。
4. 核对配置后手动运行合成任务和停止流程。新版本中保存的 Cmd、自动重启设置及其他升级后编辑不会自动合并到旧副本；旧版不能导入 schema 6 导出去完成降级。

没有兼容备份时，先保留原件，在独立目录用旧版重新创建其支持的配置，并重新录入需要的敏感值。不存在受支持的原地降级工具。不要在旧程序报格式不支持时覆盖或删掉 schema 6 原件。

## 失败时保留什么

读取或保存失败时保留工作区原件、备份和实际错误类别，先退出再处理；遇到外部修改提示不要强行覆盖。密文无法解密时原数据应保留，重新录入只在明确选择的副本上进行。日志迁移失败不等同于配置升级失败，不要通过删除原日志来重试。故障记录分享前须去掉真实命令、路径、日志和凭据。
