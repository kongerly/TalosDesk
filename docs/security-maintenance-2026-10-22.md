# 运行时安全维护说明

更新日期：2026-10-23。

结论：v0.1.0 到 v0.3.0 的历史自包含包仍在使用 .NET 10.0.12，请停止继续分发。本地重建已经完成，但尚未发布。

## 对使用者的影响

经本地核实，v0.1.0、v0.1.1、v0.2.0、v0.3.0-preview.1 和 v0.3.0 的历史自包含包都嵌入了 .NET / Windows Desktop 10.0.12。这些包使用包内运行时，更新系统 .NET 不会替换它。

[Microsoft .NET 10 发布元数据](https://builds.dotnet.microsoft.com/dotnet/release-metadata/10.0/releases.json)把 2026-10-13 的 10.0.13 标记为安全更新，配套 SDK 为 10.0.402。本说明只核实组件基线，不声称每个 .NET 漏洞都能通过 TalosDesk 触发。

## 修复与分发状态

- 当前源码已固定 SDK 10.0.402、自包含运行时和 ProtectedData 10.0.13。
- 当前 rc.1 和基于 v0.3.0 的稳定版维护副本都已完成本地重建，但尚未发布；历史远端附件没有替换，不能视为已经修复。
- 后续隔离调查已在 rc.1 复现同一迁移问题，且不加载 TalosDesk、不并行测试的嵌套目录复制/重命名也可触发 Windows 错误 5，短暂等待后可成功。具体占用来源尚未确认，不能归因为测试隔离或特定安全软件。当前源码与 schema 4 维护副本已加入有界重试及持续失败/目标冲突回归；单工作线程通过不再作为修复依据。
- 修复后的两个副本已通过默认并发完整测试、Release 构建及本地打包。rc.1 稳定化 ZIP 已补测成功/失败、运行/停止/强停、分组、有限重启耗尽、日志迁移及强制结束后的归属清理和中断历史。后续 schema 6 开发包另已复核日志搜索、Cmd 双通道/强停、默认 PowerShell，以及等待中退出确认的暂停、返回保留预算和确认退出取消等待；最后一次确认由用户点击，退出后核对没有新建会话或残留归属子进程。等待中直接点击“停止”仍只由包内 WPF 回归覆盖，schema 4 维护包也尚未执行完整 EXE 操作链。干净客户端、跨账户 DPAPI、多屏/DPI、真实托盘鼠标和通知区域重建仍未验证，产物仍未签名。

运行时更新本身不改变应用功能或配置格式：v0.3.0 维护副本保留 schema 4，稳定化阶段的 rc.1 产物使用 schema 5。之后的 Windows Cmd 开发改动另将工作源码升级到 schema 6；维护副本不包含日志搜索或 Cmd。schema 4 维护包不能读取 schema 5/6，此前 schema 5 的 rc.1 也不能读取 schema 6，回退必须使用兼容备份。应用版本号和渠道尚未为这些新增改动重新分配，本地开发包不能直接作为正式版本分发。同版本只增加 SemVer 构建元数据不会触发更新提示，正式分发必须使用明确的版本与渠道。

## 后续脱敏修复

主线随后修复了令牌模式与已知敏感值匹配的交互问题（提交 `9adcbf8`）：当敏感值包含空格、制表符或换行，且位于 `Bearer `、`token=` 或 `api_key=` 模式值中时，旧逻辑可能在内部空白后输出敏感值的剩余片段。修复适用于新捕获的 stdout/stderr，不会追溯清理旧日志或目标程序另写的文件。

主线还修复了已知敏感值首尾重叠时的后缀泄露：遮蔽第一个值时，仍检查其内部开始的其他值，合并遮蔽全部重叠范围。重叠含换行或跨输出块时也遵循此规则，不会因为先匹配了一个值而跳过另一个值的开头。

此外，主线修复了已知值与令牌模式前缀交叠时的遗漏：旧逻辑整段输出前缀时可能暴露其中的已知值，而先遮蔽已知值或另一个令牌时也可能跳过新模式的起点。现在前缀逐字符接受已知值检查，遮蔽区域内的模式仍省略其后续值，跨块或已知值含换行时也保持一致。

主线还修复了脱敏失败提示的发布时机：输出流未结束时，不再等待换行或结束才显示固定提示；此前已脱敏的半行先独立发布，避免提示在长度边界被拆开。失败后仍省略后续原文并排空输入，同一次失败只提示一次。该修复也已适配到独立 schema 4 补丁副本。

上述脱敏修复已在独立的 schema 4 源码副本完成适配，并通过完整 Core 测试，包括逐分块脱敏、长重叠链、模式前缀交叠、独立完整文本覆盖校验及真实合成命令的双通道事件、内存和磁盘日志检查；配置仍为 schema 4，没有引入新功能线的恢复或 Shell 行为。原维护副本及此前生成的维护 ZIP 保持原样，尚不包含这些脱敏修复，之前的完整构建和打包结果不能作为补丁副本的验收依据。

2026-10-25，[独立维护审阅分支](https://github.com/kongerly/TalosDesk/blob/ac0fbbec6e31cd789c81ed303d33a543c35e95c1/docs/maintenance-review.md)已整合这些修复，并在[该分支自己的 CI](https://github.com/kongerly/TalosDesk/actions/runs/40113332511)完成 Core/App 全量测试、Release、`scripts/Publish.ps1` 和静态包核验。ProtectedData 显式依赖也已更新为 10.0.13，包内实际版本已核对。最终 EXE 人工验收与正式定版仍未完成，不能作为已发布维护包分发，详见[发布说明草稿](release-next-draft.md)。

## 后续日志修复

主线及独立 schema 4 补丁副本还修复了历史清理部分失败后的容量计数：文件占用可能使删除只完成一部分，旧计数却仍包含已经删除的数据，进而阻止空间足够的活动日志继续落盘。现在清理错误仍会报告，失败后按现存批次重算容量；重算也受阻时保留原有保守计数。已经删除的历史不会回滚。

主线及独立 schema 4 副本另已修复本次活动批次元数据丢失后的收尾：重算容量后，用仍持有的批次状态尝试重建完成记录，保留结果、退出码和原有完整性标记。整个批次目录或输出已丢失时，不会恢复输出内容；没有本次状态的历史批次仍按损坏元数据规则处理。

两份源码还修复了日志流关闭错误中断收尾的问题：一项关闭遇到 IO 或权限错误后，仍尝试关闭另一通道、记录写入失败、释放本批次并尝试保存真实结果，避免留下永久阻止迁移的活动保护。此修复不恢复未刷新的数据，也不能保证持续故障的文件系统允许保存、迁移或清理。

这些日志修复已通过隔离 Core 验证，原维护副本和旧维护 ZIP 尚未纳入。它们与上述脱敏补丁须从最终维护源码一并重新构建、打包和验收，不能沿用旧维护包的验证结果。

独立维护审阅分支另已适配桌面收尾警告：底层仅设置写入失败标记时也显示警告，保留已有的本轮警告，新运行成功建立日志批次后清除旧警告，旧运行迟到的输出通知不覆盖新状态。对应桌面回归已在该分支 CI 实际通过，覆盖锁住完成记录时保留真实退出结果及再次运行。该适配仍未进入保留的原维护副本或旧维护 ZIP。

可用的替代版本将列在[官方发布页](https://github.com/kongerly/TalosDesk/releases)。更换应用前，先停止命令、退出应用，并备份完整工作区及所需旁文件，再把新包解压到新目录。可分享导出不含敏感值，不能代替完整备份。操作步骤见 [README](../README.md#手工升级)。
