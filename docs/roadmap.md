# TalosDesk 开发与发布路线图

更新日期：2026-10-01。

本路线结合后续开发建议、当前 README、设计说明、发布脚本及关键进程实现整理。它区分已发布能力、当前版本能力和待办。v0.2.0 已完成 T07 更新检查、T08 本地崩溃诊断、维护文档、全新 Win11 与双账户 DPAPI 验收，并以稳定渠道进入发布。T01–T06 的阶段性限制保留为历史记录；R6 虚拟机验收后的本地时间显示调整按约定只做本机自动化、Release 构建和发布脚本验证。

## 方向与执行顺序

TalosDesk 继续聚焦 Windows 本地多项目、非交互命令的运行管理，逐步把进程存活、服务就绪和输出追溯分别做好。近期顺序为：**当前分支收口与隐私保护 → 更新分发与维护 → 就绪检查 → Windows 多 Shell**。

- 每个候选版本只引入一个主要主题；安全修复、回归测试和文档随功能交付。
- 优先复用已有进程归属、分组、导入预览和日志机制，不重新建设已完成能力。
- 最小 CI 提前到下一版本，Windows 客户端兼容验收独立安排；单人维护不同时铺开全部子系统。
- 新平台、新 Shell、自动重启等能力必须先证明归属控制和异常路径可验证，再进入发布范围。
- 版本号是规划目标，周期是单人有效开发时间的粗估，不是日历承诺。每个里程碑结束后依据缺陷和用户反馈重新估算；后期候选功能可以拆版或取消。

不采用“留存必然提升”或“用户基数翻倍”等未经验证的收益判断。优先级依据是敏感信息暴露风险、核心场景价值和长期维护成本。

## v0.1.1：分支收口与隐私保护（已发布公开预览）

以下保留原任务清单；分批实际结果见 T01–T06 记录。未勾选项目不因发布而自动视为验收通过。

### 1. 先建立回归基线

- [x] 盘点未发布功能和现有测试，形成与候选包对应的变更说明；已完成干净 Windows 11 x64 环境验收。
- [x] 接入最小 Windows CI：还原、Release 构建、全量自动化测试；候选包继续通过 `scripts/Publish.ps1` 生成并验证 SHA-256。
- [ ] CI 使用独立临时工作区和合成命令，覆盖中文/空格路径、缺失 PowerShell、启动失败、异常退出、Ctrl+C、超时强停及应用异常退出后的归属进程清理。
- [ ] 记录 runner 的操作系统和 PowerShell 版本。托管 Windows runner 上通过的结果不能代替 Windows 10/11 桌面客户端验收。

### 2. 为敏感值提供明确入口

- [x] 命令配置增加环境变量项及显式敏感标记；普通值与敏感值分别处理，不尝试从任意 Shell 命令文本中自动识别并加密密码。
- [x] 敏感值使用 Windows DPAPI `CurrentUser` 保护，仅在启动目标进程时解密并注入其环境；不拼接到命令行，不修改应用全局环境，避免并发命令互相污染。
- [x] 使用最小必要的存储边界封装 DPAPI，仅服务当前 Windows 实现；本阶段不预建 Keychain、Secret Service 或跨平台凭据框架。
- [x] 配置升级到 schema 3，兼容读取 schema 1/2；读取不自动重写文件，保存升级应原子完成，失败保留原文件。旧版拒绝新 schema 的行为已经验证。
- [x] 导出默认仅保留敏感变量名和待填写标记，排除敏感明文及本机 DPAPI 密文；导入先预览，敏感值未补齐时禁止启动依赖它的命令，并说明原因。
- [x] 无法解密、密文损坏或跨账户迁移时保留原数据并提示重新录入，不静默置空或回退到明文。

DPAPI 的保护范围选择依据见 [Microsoft DataProtectionScope 文档](https://learn.microsoft.com/en-us/dotnet/api/system.security.cryptography.dataprotectionscope?view=net-10.0)。`CurrentUser` 面向当前用户上下文，不能防御同用户权限下的恶意程序；本机密文不作为跨设备便携凭据格式。运行中的目标进程仍能访问注入值，环境变量不是进程间的保密边界。用户已写进命令或旧文件的秘密不会被这项功能自动消除。

### 3. 在输出进入显示和存储前脱敏

- [x] 以本次运行已知敏感值精确遮蔽为基础，辅以有边界、有超时限制的常见令牌模式；不以引入某个日志库作为完成标准。
- [x] 同一脱敏结果进入实时显示、内存缓冲、stdout/stderr 文件及相关诊断信息，避免只隐藏界面但仍明文落盘；复制内容沿用显示结果。
- [x] 测试跨读取块、跨行、Unicode、短敏感值、大量输出、匹配超时和误遮蔽；无法安全处理的片段应省略并提示，不回退记录原文。
- [x] 既有历史日志不自动改写，明确提示旧文件仍可能含敏感信息，并沿用实际路径和清理入口；迁移后的旧目录残留提示继续保留。

不承诺识别全部秘密、编码后的值或目标程序写入其他文件的内容。只对 TalosDesk 自己的输出处理与存储路径作验收；脱敏不得影响目标进程收到的真实配置。

### 4. 隐私说明与发布材料

- [x] 新增隐私说明，列出工作区、日志、位置记录和诊断文件的位置、内容、保留和清理方式；分别说明 TalosDesk 与用户命令的联网行为。
- [x] 明确当前不收集产品遥测。本阶段不增加遥测管线；若未来引入，必须默认关闭，且 `DO_NOT_TRACK=1` 覆盖应用中的开启选项，并配套无请求测试。
- [x] README、编辑器、导出预览和发布说明统一说明明文命令、加密范围与脱敏限制；保留校验教程，明确当前是否签名。

**完成条件**：使用合成凭据验证保存、重新打开、并发注入、解密失败、schema 升级、脱敏与导出；新功能产生的文件和诊断中无测试敏感明文。导入不运行命令，缺失敏感值不被空值替代，旧工作区不损坏。核心测试通过后，再验收桌面编辑、导入预览、历史日志与分组运行路径。

## v0.3.0：就绪检查与项目汇总

- [ ] 对服务命令增加可选 TCP 探测，首版限本机回环地址，配置端口、间隔、单次连接超时、启动等待期限及连续失败阈值。
- [ ] 保留进程生命周期和退出结果，另设探测状态：未配置、等待中、探测通过、超时/不可达；只有进程仍在运行且最近探测符合策略时才显示“已就绪（TCP 探测通过）”。
- [ ] 持续更新探测结果：已就绪后不可达会撤销就绪，超时后恢复可以再次通过；探测失败不直接等同进程退出，也不自动停止或重启命令。
- [ ] 每次重启生成新的探测周期，旧回调不得覆盖新状态；进程退出、停止和应用关闭时取消相关探测。
- [ ] 项目概览按唯一命令统计“X 个运行中，其中 Y 个探测通过”；未配置探测的服务不计入已就绪，加入多个分组的命令不重复计数。
- [ ] 一键运行继续要求选择命令或已有分组，不默认运行项目全部命令；顺序分组仍限成功完成的任务，不顺带增加服务依赖编排。

**完成条件**：合成 TCP 服务覆盖立即/延迟监听、超时、恢复、运行中失联、退出、停止与快速重启。测试包含端口预先被其他程序占用的场景；文案明确 TCP 可达不能证明响应者属于该命令，也不能证明业务健康。

### v0.3.x 候选：有限自动重启

作为独立迭代，默认关闭、只针对服务的意外退出；明确最大次数、退避上限和重试计数重置条件。手动停止、应用退出、分组取消及同组失败导致的清理必须取消重试。首版可只允许独立运行的服务开启，避免改变现有分组“任一失败则清理本次启动成员”的语义。

只有上述策略和竞争条件测试可独立验收时才排期；不因 TCP 探测失败、内存超限或任务成功退出而自动重启。

## v0.4.x 及后续候选

### Windows 多 Shell

先实现 Cmd，之后单独验证 Git Bash，再按反馈决定 PowerShell 5.1。实际加入第二种 Shell 时才提取最小适配边界：可执行文件定位、参数与引用规则、环境变量、编码及退出结果；进程归属仍沿用共同约束。补全和语法着色按 Shell 区分，不让 PowerShell 补全误用于其他语法。

每种 Shell 都要覆盖中文/空格路径、引号、子进程、Ctrl+C、强制停止及端口释放。Git Bash/MSYS2 的行为通过具体版本和复现场景验证，不预先断言必然逃逸，也不通过进程名扫描强行接管未知进程。Python 脚本目前可由 PowerShell 调用，直接可执行文件模式按真实需求另评估，不将 Python 解释器混同于 Shell。

### 探测、搜索与 WSL

HTTP、日志关键字和当前日志文件搜索按反馈分别排期；跨历史批次全文索引先评估存储、脱敏与性能成本。新增探测仍只描述已验证的响应条件，不自动宣称进程归属。

WSL 先做归属与清理验证。不能把终止整个共享发行版作为普通命令停止策略；无法证明只影响本次启动任务时，不开放管理能力。ConPTY 和交互式 CLI 视为独立产品范围，不默认纳入 v0.5.x。

### 暂不承诺

跨平台、后台服务器/无头运行、云账号、强制遥测、插件市场、全能 IDE、内存阈值自动重启和静默更新均不纳入当前交付范围。跨平台仅记录未来需替换的 WPF、进程管理和凭据边界，不提前建立目录或抽象；有需求与维护资源后再评估 Linux，macOS 更后。

## 所有版本的验收与发布门槛

1. 先验证核心行为，再进行桌面界面检查。测试只使用独立临时目录、隔离配置、合成命令与占位凭据。
2. 行为变更必须有对应测试并同步文档。候选版本必须通过完整自动化测试、Release 构建和 `scripts/Publish.ps1`；每次报告实际执行、未执行及已知限制。
3. 桌面验收至少覆盖命令启动、成功/失败、停止、强停、重启、并发、分组、导入预览、异常关闭和日志失败路径；包能启动不等于通过验收。
4. 兼容矩阵分层：每次变更运行可自动化的核心测试；候选版补干净 Win11 x64 客户端与选定 PowerShell 7 版本；Win10 和新增 Shell 按各自准入条件扩展，并保存结果。
5. 发布附件核对版本、运行时、安全更新、ZIP 与 SHA-256 一致性、许可及隐私内容；不包含用户日志、真实工作区或凭据。签名状态和未验收平台明确披露。
6. 只管理本次启动且能确认归属的进程。Ctrl+C 依赖目标共享控制台及信号处理，Job 清理仅覆盖仍归属于该 Job 的进程；不以 CloseMainWindow 作为通用 CLI 停止步骤。边界参见 [Windows Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)。
7. 本地准备与验证不等于外部发布授权；提交、推送、打标签、发布或其他外部仓库变更仍须遵守项目协作约定。

v1.0.0 额外要求：核心启动/停止和数据迁移无已知阻塞缺陷；在声明支持的客户端环境有可复现验收；用户反馈形成修复闭环；备份恢复、隐私、安装升级与贡献文档齐全。多 Shell、WSL、交互终端和跨平台并非稳定版必选项。

T02 必须确定以下规则，后续实现及测试以此为准：

- **变量校验**：变量名按 Windows 规则忽略大小写判重；拒绝空名、含 `=` 或 NUL 的名称及含 NUL 的值。明确配置覆盖继承值的规则；“待填写”与显式空字符串是不同状态，不用空值暗示删除。
- **启动失败**：缺少敏感值或解密失败时，不创建目标进程。分组在启动前检查本次实际要启动的成员，已知配置错误时整次分组不启动；通过检查后仍可能发生的启动失败继续沿用现有清理策略。
- **导入冲突**：预览标出会替换的敏感配置；确认覆盖后，以导入的待填写状态为准，不隐式复用本机旧值。保留原命令的冲突选择则同时保留其原配置。
- **编辑与迁移**：关闭或取消编辑不清空秘密，保存失败不丢失旧密文；升级不自动生成含明文的额外副本。需要备份旧配置时说明其原有明文风险和位置。
- **输出边界**：两个输出通道各自处理边界残片；约定最大敏感值长度、残片缓冲上限、结束时处理方式和模式匹配超时。无法安全处理时省略片段并提示，原文不能从异常信息或备用日志路径绕过脱敏。
