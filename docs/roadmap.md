## 3. 已确认的推进顺序

### 第一步：验证命令执行与进程管理

目标：打通“启动 → 获取日志 → 停止及子进程清理”。

先使用独立临时目录和可控测试程序验证普通退出、失败、大量输出和子进程场景。
在得到真实项目运行授权后，验证 go run、uv 等启动方式的实际表现。

验收重点：

- [ ] 工作目录正确，启动失败有明确结果。
- [ ] 能持续读取输出，任务退出码与状态对应。
- [ ] 能停止归属于本应用的进程及受支持的子进程，不影响外部启动的程序。
- [ ] 停止、重复运行、重启与异常退出遵守事先确认的契约。
- [ ] 核心自动化测试可重复执行。

阶段结果应明确支持范围与尚未验证的情况，未验证的启动器不能宣称已兼容。

### 第二步：完善界面与配置

目标：形成用户可以直接操作的项目与命令工作台。

验收重点：

- [ ] 可添加、查看、编辑项目和命令，并复制实际命令。
- [ ] 配置可保存、导入、导出；应用重开后恢复配置，导入不自动执行。
- [ ] 多个项目可同时运行，切换选项不停止任务，各命令输出分别展示。
- [ ] 界面显示开始时间、运行状态及退出结果，大量输出时仍可操作。
- [ ] 有任务运行时关闭应用，提供已确认的退出选择并正确处理停止结果。
- [ ] 数据保存失败、配置损坏和导入冲突按确认的规则处理。

### 第三步：真实项目试用与发布验证

目标：在用户实际工作流程中验证用途与可靠性，产出 Windows x64 发布包。

验收重点：

- [ ] 经用户确认后使用 试用项目 A、试用项目 B 的真实运行配置。
- [ ] 启动、测试和检查命令在正确目录执行，结果与终端直接执行一致。
- [ ] 两个项目同时运行时，日志分开、界面保持响应。
- [ ] 停止、重启以及关闭应用后的进程情况均有实测结果。
- [ ] 中文路径、带空格路径、命令不存在、异常退出、大量输出和配置损坏得到验证。
- [ ] 发布包脱离开发启动方式可以运行；所需项目工具环境有明确说明。
- [ ] 实际功能、使用说明、已知限制和验证结果一致。
- [ ] 用户完成真实试用并确认能减少查找命令的操作。

## 4. 首版完成标准

用户能够保存自己的项目命令，在以后重新打开应用时直接运行，清楚看到执行结果，并可靠停止受管理的任务。
核心异常路径有自动化验证，桌面操作和真实项目行为有试用记录，发布包可重复构建与启动。
功能验收未完成时不标记首版完成；不把存在测试文件当作测试已经通过。
