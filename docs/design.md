# TalosDesk 设计说明

## 产品定位

TalosDesk 是面向个人开发者的 Windows 本地项目运行工作台。它保存已经确认的项目命令，使用户不必反复查找启动、测试和检查命令，并集中展示执行状态和输出。

核心流程是：选择项目、选择命令、运行、查看输出和结果、按需停止或重启。首版为单用户、Windows 单机应用，核心功能不依赖模型 API 或独立后端服务。

## 首版行为

| 能力 | 行为 |
| --- | --- |
| 项目管理 | 添加和编辑本地项目名称与目录；工具程序目录也可作为项目，不要求包含源码 |
| 命令配置 | 保存名称、用途、实际命令、工作目录与任务或服务类型；支持双击编辑和鼠标拖动排序，并保留按钮入口 |
| 命令执行 | 使用 `pwsh -NoProfile -NonInteractive -Command` 执行，不读取 PowerShell profile |
| 运行管理 | 支持运行、停止、重启和批量启动；同一命令不能重复运行，不同命令可以并行 |
| 命令分组 | 分组隶属于单个项目，同一命令可加入多个分组；分组成员有独立顺序 |
| 分组执行 | 同时模式启动全部空闲成员；顺序模式仅支持任务，并在失败或停止后终止队列 |
| 输出 | 分别展示标准输出和诊断输出（stderr）；可像终端一样按字符或跨行选择，并通过 `Ctrl+C` 或右键复制；选中内容或滚离底部时暂停自动跟随；每次运行仅保留最近 10,000 行内存日志 |
| 配置 | 本地 JSON 持久化；支持导入、导出和冲突预览；导入后不自动执行命令 |
| 退出 | 有命令运行时，允许停止任务后退出或返回应用 |

主窗口包含项目概览、命令管理、分组管理和运行输出四页。切换项目或页面不会停止正在运行的任务，日志在当前应用会话内按命令隔离。分组页展示成员执行轨道，但不合并各命令的日志。

## 分组执行原则

- 同时分组按保存的成员顺序发起命令，但不等待前一条完成；已占用成员被跳过，其余成员继续启动。任一成员运行失败时，TalosDesk 会停止由该分组启动且仍在运行的其他命令，并显示失败命令、退出码与清理结果；不会停止手动启动或仅被该次执行跳过的命令。
- 顺序分组启动前会预留全部成员，防止手动运行或其他分组抢占；前一条任务成功后才启动下一条。
- 顺序任务启动失败、非零退出或由用户停止时，剩余成员不再运行。停止当前命令即终止该顺序队列。
- 顺序队列活动期间不允许修改或导入工作区；查看输出、停止当前命令和导出配置仍可使用。
- 应用退出时先取消尚未启动的顺序步骤，再按既有进程归属规则停止当前实例已经启动的命令。

## 进程管理原则

- 只管理由当前应用实例启动并能可靠确认归属的进程。
- 停止时先向命令进程组发送 Ctrl+C，等待 5 秒；仍未退出时强制结束归属进程组并确认结果。
- 启动成功只表示进程已经创建；“运行中”不代表服务已就绪。
- stderr 仅表示进程写入了诊断通道，不代表命令失败；最终成功或失败以进程退出状态和退出码为准。
- 正常完成、执行失败和用户停止使用不同状态。
- 工作目录始终来自保存的命令配置，不依赖应用启动时的当前目录。
- 首版不提供完整交互终端；需要密码输入、REPL 或交互选择的命令应在外部终端运行。

## 配置和隐私边界

工作区 schema 版本为 2，默认保存在 `%LOCALAPPDATA%\TalosDesk\workspace.json`。项目路径、命令、用途说明和分组成员关系以明文 JSON 保存，导出文件同样为明文。schema 1 文件会以无分组工作区载入，并在下一次保存或导出时升级为 schema 2；旧版本应用会拒绝 schema 2，避免忽略并覆盖分组数据。

TalosDesk 不提供凭据存储、命令内容加密或导出脱敏。用户应通过环境变量或外部凭据工具向目标程序传递敏感值，不应把密码、令牌或 API 密钥直接写入命令。命令编辑器和导出流程会提示这一限制。

## 技术与发布范围

| 部分 | 选择 |
| --- | --- |
| 应用语言 | C# |
| 平台 | .NET 10 / WPF |
| 配置 | 本地 JSON 文件 |
| 首版系统范围 | Windows 11 x64 |
| 交付 | 包含 .NET 运行时的便携 ZIP |
| 外部命令宿主 | PowerShell 7，必须能从 `PATH` 找到 |

其他 Windows 版本不被主动阻止，但 v0.1 不承诺兼容。Go、Python、uv 等目标项目工具不包含在发布包中。首版不包含安装程序、代码签名、后台托盘、服务探活或自动命令识别。
