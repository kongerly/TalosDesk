# TalosDesk 设计基线

确认日期：2026-09-23。状态：方案已确认，尚未实现。

本文保存讨论中已确认的产品与技术方向。未定细节单列，不把本文作为创建工程或启动开发的授权。

## 1. 定位与用户问题

TalosDesk 是面向个人开发者的 Windows 本地项目运行工作台。
核心问题是：切换项目后忘记启动、测试和检查命令，需要翻记录或再次询问，并希望集中查看执行结果。

核心流程：选择项目、选择已确认命令、执行、查看输出和结果、按需停止或重启。
成功标准是用户能够更少地查找命令，并清楚知道程序是否运行、任务是否成功、停止是否完成。

首版为单用户、Windows 单机、本地项目。核心能力无需模型 API。
试用项目 A 和 试用项目 B 是计划中的真实试用对象，其完成进度不是 TalosDesk 的运行依赖。
本项目不改变 其他项目 C、其他项目 D 或其他项目的学习和开发安排。

## 2. 首版功能范围

| 能力 | 已确认行为 |
| --- | --- |
| 项目管理 | 添加、查看、编辑本地项目名称与目录 |
| 命令配置 | 保存名称、用途、实际命令、工作目录与运行类型；目录默认使用项目目录，也可指定子目录 |
| 执行 | 支持持续运行的服务和执行后结束的任务，首版无需中途输入 |
| 运行管理 | 运行、停止、重启；切换项目不停止任务，可同时运行不同项目 |
| 输出与结果 | 各命令分别展示实时输出、开始时间、运行状态与退出结果 |
| 命令复用 | 查看、编辑和复制实际命令，便于在 VS Code 终端继续学习或交互操作 |
| 配置持久化 | 应用重开后可恢复项目与命令配置；支持导入和导出 |
| 退出行为 | 有任务运行时，关闭应用提示“停止任务并退出”或“返回应用” |

首版通过手动配置和导入建立运行入口。Agent 可在得到相应授权后读取项目说明并整理配置，由用户核对后导入。
这项协作方式不意味着应用内置 Agent 或运行时调用模型。

配置导入不自动执行其中的命令。配置持久化也不意味着重启后自动启动任务或接管先前进程。

## 3. 界面布局

| 区域 | 内容 |
| --- | --- |
| 左侧项目列表 | 项目名称、是否有任务运行，以及添加和编辑入口 |
| 右侧项目详情 | 项目路径、保存的命令及用途 |
| 命令操作区 | 运行、停止、重启、编辑和复制 |
| 下方输出区 | 选中命令的日志、开始时间、运行状态和退出结果 |

状态同时使用文字和颜色表达，如“运行中”“执行成功”“执行失败”“已停止”。
这些是产品语义示例，不是已经冻结的内部状态机。

界面应保持简洁；切换项目或查看其他命令时，正在执行的任务继续运行。
首版输出区用于查看输出，不承担完整交互终端的功能。
需要密码输入、交互选择或 REPL 的命令，可复制到外部终端执行。

## 4. 运行管理原则

- 启动成功只说明进程已创建，不能据此宣称服务可用；“运行中”和“服务已就绪”必须区分。
- 只管理本应用启动并能可靠确认归属的进程，不按程序名称结束用户在其他终端启动的进程。
- 启动器退出不一定等于其子进程全部退出，停止结果须有实际验证依据。
- 停止、重启、重复点击运行、启动失败和异常退出都应给出清楚的结果。
- 正常完成、执行失败和用户停止需要区分，不能全部当作“成功”。
- 配置记录工作目录，避免依赖启动应用时的偶然目录。
- 大量日志不能持续阻塞界面或导致资源无界增长，具体限制在实现前明确。
- “停止任务并退出”应处理所管理任务的停止结果；具体超时和失败交互仍待确认。

Windows 进程管理是首轮技术验证重点，尤其是通过 go run、uv 等启动器执行程序后的子进程行为。
Windows Job Objects 是可评估的实现机制，不表示已经验证或选定完整停止方案。

## 5. 技术基线

| 部分 | 已确认选择 |
| --- | --- |
| 应用语言 | C# |
| 运行平台 | .NET 10 |
| 桌面界面 | WPF |
| 配置存储 | 本地 JSON 文件 |
| 首版交付 | 包含 .NET 运行时的 Windows x64 发布包 |

WPF 与 Windows 单平台目标匹配，界面和运行管理使用同一技术体系。
当前配置规模适合本地文件，无需在首版引入数据库服务。

发布包包含应用需要的 .NET 运行时，不代表包含所有目标项目的开发工具。
Go、Python、uv 等仍由目标项目的运行环境提供。应用无需用户先启动独立后端服务。
自包含发布会增加包体积，运行时更新需随应用重新发布。

SDK 补丁版本、第三方依赖、测试框架、安装方式和实际构建命令在开工时确认。
与 其他项目 C 采用相同技术方向不构成代码复用或共同开发的授权。

## 6. 留待试用后评估

- 自动扫描项目并推荐命令：只有新增项目的配置负担确实明显时，再决定是否加入；候选仍需用户确认。
- 后台托盘运行：首版采用关闭时停止并退出或返回应用的交互，托盘另行评估。

上述内容不属于首版验收范围，也不承诺后续一定实现。

## 7. 实现前需要补齐的细节

这些是已有功能必须明确的契约，当前尚未作最终决定；在对应实现前处理，不据此提前扩大范围。

| 待确认项 | 需要明确的问题 |
| --- | --- |
| 命令执行方式 | 使用的 shell 或可执行文件调用方式、参数与引用规则、PATH 和环境继承，是否读取 shell profile |
| 停止与退出 | 正常停止和强制结束的边界、超时、子进程归属，以及应用异常退出后的行为 |
| 重复运行和重启 | 同一命令的并发策略、停止失败后能否重启，运行中修改配置如何生效 |
| 日志与状态 | 编码、标准输出与错误输出、容量限制，是否及保留多久的历史日志 |
| 配置文件 | schema、存储位置、保存失败恢复、导入冲突、相对目录基准以及敏感值处理 |
| 服务就绪 | 首版是否提供可配置探活；未配置或未实现时仅显示进程状态 |
| 环境与分发 | 最低支持 Windows 版本、所需命令环境、便携包或安装包，以及依赖版本与许可 |

涉及产品行为的未定项向用户确认；具体代码组织按已授权范围采用最小可行实现。
