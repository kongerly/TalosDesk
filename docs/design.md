# TalosDesk 设计说明

## 产品定位

TalosDesk 是面向个人开发者的 Windows 本地项目运行工作台。它保存已经确认的项目命令，使用户不必反复查找启动、测试和检查命令，并集中展示执行状态和输出。

核心流程是：选择项目、选择命令、运行、查看输出和结果、按需停止或重启。首版为单用户、Windows 单机应用，核心功能不依赖模型 API 或独立后端服务。

## 首版行为

| 能力 | 行为 |
| --- | --- |
| 项目管理 | 添加和编辑本地项目名称与目录；工具程序目录也可作为项目，不要求包含源码 |
| 命令配置 | 保存名称、用途、实际命令、工作目录与任务或服务类型；支持双击编辑和鼠标拖动排序，并保留按钮入口；编辑器提供 PowerShell 语法着色、多行输入、成对符号以及不执行输入内容的本地安全补全 |
| 命令执行 | 使用 `pwsh -NoProfile -NonInteractive -Command` 执行，不读取 PowerShell profile |
| 运行管理 | 支持运行、停止、重启和批量启动；同一命令不能重复运行，不同命令可以并行 |
| 命令分组 | 分组隶属于单个项目，同一命令可加入多个分组；分组成员有独立顺序 |
| 分组执行 | 同时模式启动全部空闲成员；顺序模式仅支持任务，并在失败或停止后终止队列 |
| 输出 | 分别以纯文本展示标准输出和诊断输出（stderr），捕获前关闭 PowerShell ANSI 样式；可像终端一样按字符或跨行选择，并通过 `Ctrl+C` 或右键复制；选中内容或滚离底部时暂停自动跟随；每次运行仅保留最近 10,000 行内存日志，磁盘日志按批次保存与轮转 |
| 配置 | 本地 JSON 持久化；支持导入、导出和冲突预览；导入后不自动执行命令 |
| 退出 | 有命令运行时，允许停止任务后退出或返回应用 |

主窗口包含项目概览、命令管理、分组管理和运行输出四页。切换项目或页面不会停止正在运行的任务，日志在当前应用会话内按命令隔离。分组页展示成员执行轨道，但不合并各命令的日志。运行输出页的批次选择、日志设置与操作按钮会随可用宽度换行，日志警告使用独立可换行区域，确保在最小窗口宽度和放大显示下仍可访问。

磁盘日志默认位于工作区文件旁的 `<工作区文件名>.logs`；用户可在输出页选择其他父文件夹，程序在其中用工作区路径摘要建立专属日志子目录，避免不同工作区共用数据。更改位置要求当前没有写入中的批次，迁移历史日志及设置后才切换位置记录；目标目录已存在时拒绝覆盖。位置记录是工作区文件旁的 `.log-location.json` 文件，导入导出不包含它。日志按项目 ID、命令 ID、批次 ID 分层，stdout/stderr 独立存放；批次元数据记录起止时间、结果和截断或写入失败状态。启动时将尚未完成的旧批次标为中断。每工作区默认上限 500 MB、30 天，用户可在输出页修改；清理时先删除过期批次，再按开始时间从旧到新删除已结束批次。运行中的批次不会被删除；容量耗尽时该批次后续输出不再落盘并提示，进程继续运行。输出页可切换历史批次并分别查看两个通道的最近 10,000 行，也可打开目录或确认后清理已结束批次。“清空显示”不删除磁盘日志。

批次目录枚举与元数据解析分开：在日志根目录内按项目、命令、批次三级 GUID 目录统计文件容量，继续跳过非 GUID 目录和重解析点。`run.json` 损坏、缺失、为空或身份与目录不符时，历史列表不展示该批次，但容量统计及清理仍包含它。元数据有效时按开始时间排序与判断期限，否则以批次目录的 UTC 修改时间代替；未运行批次参与自动轮转和手动清理。当前写入批次由内存中的活动 ID 集合保护，以目录中的批次 ID 判断，不依赖元数据解析或其中的状态字段。写入失败后的容量重算同样覆盖损坏批次。

## 应用提示窗口

错误、警告、信息提示与操作确认共用应用内 WPF 提示窗口。窗口沿用浅蓝渐变背景、白色圆角卡片、深蓝正文、标题与正文字体及编辑窗口按钮样式；信息和询问使用蓝色，警告使用暖色，错误使用暗红色，同时显示状态图标与中文类别。系统标题栏和应用图标与编辑窗口一致，文件及文件夹选择器仍使用系统窗口，页面内非阻塞提示条保持原有行为。

提示默认宽度为 560 逻辑单位，高度随内容增长，最高为 640 逻辑单位并进一步受所有者所在屏幕工作区限制。正文自动换行、可滚动、选中和复制，底部操作按钮固定可见。窗口相对发起者居中并限制在屏幕内，编辑窗口上的提示以该编辑窗口为所有者；关闭后返回原焦点，不持久化提示窗口布局。启动参数错误在主窗口创建前也使用同一提示，提供任务栏入口。

单按钮提示使用“确定”；删除使用“取消／删除”，清理使用“取消／清理”，导出使用“取消／继续导出”，运行中退出使用“返回应用／停止并退出”。导入冲突使用“取消导入／保留本机／替换”，分别映射原有取消、保留与替换分支，确认覆盖仍使用导入项整套配置。所有确认默认聚焦取消或返回，Enter 只激活当前聚焦的按钮，Esc 与关闭按钮都返回取消分支；单按钮提示支持 Enter、Esc 关闭。导入仍先展示完整预览，任何提示或确认本身都不运行命令。

## 窗口状态与自适应布局

### 系统托盘

应用运行期间创建一个使用现有应用图标、提示当前工作区身份的系统托盘图标。最小化时只在图标注册成功后隐藏主窗口及任务栏按钮，后台命令、分组、输出与日志继续运行。左键单击图标恢复，右键菜单提供“显示主窗口”和“退出”；图标可能由 Windows 放入通知区域折叠菜单。

托盘控制器保留最小化前的普通或最大化状态以及普通窗口边界，恢复与同一工作区重复启动共用入口；重复启动仍遵守原有工作区重载条件。右上角“×”保持退出语义，托盘“退出”先恢复窗口再调用同一关闭流程。确认、异步停止与日志收尾期间阻止重复关闭；取消退出或停止失败时保留窗口与图标，并允许重试。

托盘通过 `Shell_NotifyIconW` 与 WPF 窗口消息接入，不添加第三方依赖。初次注册失败时保留普通最小化任务栏入口；收到 `TaskbarCreated` 后重新注册，失败时恢复隐藏的窗口。正常关闭后注销图标、移除消息钩子，并释放菜单及图标资源。不修改工作区 schema，不持久化隐藏状态，不增加启动隐藏、开机自启或设置开关。

### 自动恢复与布局

主窗口正常关闭时自动记录普通窗口尺寸、显示器标识、相对该屏幕工作区的位置和最大化状态，下次打开自动恢复；没有手动保存入口。状态采用工作区旁独立的 `.window-settings.json`（schema 1），不进入工作区 JSON 或导入导出。尺寸与偏移采用 WPF 逻辑单位，恢复时按目标屏幕 DPI 换算并限制在工作区内；原屏幕不存在时回到主屏幕居中。最小化保留此前普通或最大化状态，取消退出不写入，记录损坏回退默认值，写入失败不阻止退出。强制结束或断电不保证记录本次调整。

主窗口最低目标为 800 × 520 逻辑单位，可用屏幕更小时进一步限制尺寸。宽度低于 1200 时收窄侧栏，输出命令列表改为共享同一选择状态的下拉框，更新设置和诊断详情上下排列；按钮允许换行，长文本省略或换行。日志历史与设置默认折叠，警告独立展示；输出、列表及超出可视高度的内容可滚动。编辑弹窗在主窗口所在屏幕内居中并限制尺寸，底部确认和取消按钮固定，表单滚动；命令分组编辑器低于 760 宽时上下排列成员区。弹窗不单独持久化状态。

## v0.3.0：TCP 探测契约

进程生命周期与 TCP 探测状态独立；探测失败不修改退出结果，不触发分组失败清理，不自动停止或重启。仅服务命令可配置 `TcpProbe`；不增加 HTTP、业务健康检查、多 Shell 或服务依赖编排。

### schema 4 与配置

工作区 schema 4 为命令增加可空 `TcpProbe`；缺失或 null 关闭，保存时关闭字段省略。非空对象必需且仅允许下列字段，拒绝重复、未知、缺失、错误类型和越界值：

| 字段 | 默认值 | 范围 |
| --- | --- | --- |
| `Address` | `127.0.0.1` | 精确为 `127.0.0.1` 或 `::1` |
| `Port` | 必填 | 整数 1–65535 |
| `IntervalSeconds` | 2 | 整数 1–60 |
| `ConnectTimeoutSeconds` | 1 | 整数 1–60 |
| `StartupTimeoutSeconds` | 120 | 整数 1–3600，且不小于连接超时 |
| `FailureThreshold` | 3 | 整数 1–100 |

schema 1–3 默认无探测，读取不写回，下次成功保存升级为 4；旧 schema 中非空 `TcpProbe` 拒绝。schema 3/4 均保留环境变量严格结构校验。保存沿用原子替换及外部修改检测，不额外生成备份。旧应用拒绝 schema 4，回退须使用兼容副本。

编辑、复制、导出与导入合并深复制探测配置。导入预览展示完整策略，冲突替换使用导入项整套配置；无探测项覆盖会关闭原探测，保留本机项则同时保留其配置。读取、保存及预览不建立连接。任务不能携带非空探测配置；编辑器切换任务时提示保存将移除，取消与保存失败保留原配置。运行期间不允许编辑。

### 状态与时序

| `TcpProbeState` | 含义 |
| --- | --- |
| `NotConfigured` | 未配置探测 |
| `Inactive` | 未探测；停止后仍在运行时显示“探测已停止” |
| `Waiting` | 等待中，尚无成功且未到启动期限 |
| `Passed` | TCP 探测通过；阈值内失败仍保留通过并显示连续失败 n/N |
| `TimedOut` | 启动等待超时，继续探测 |
| `Unreachable` | 曾成功，随后连续失败达到阈值，撤销通过 |

成功创建会话时启动独立计时并立即尝试连接。每次连接最多等待单次超时，结束后等待检查间隔；每个会话仅一个尝试，不积压补发。成功立即关闭连接，不发送业务数据。拒绝、连接超时及套接字错误各计一次失败，主动取消不计失败。

首次成功前只按独立启动期限显示超时，不应用失败阈值；期限不因正在连接而延长。任何一次成功均进入 Passed 并清零失败数，首次成功后启动期限失效。超时及不可达继续探测，可以恢复。阈值内保留通过是去抖策略，不代表最近一次检查成功。

停止请求生效即取消探测、撤销通过；停止失败且进程仍存活时保持“探测已停止”，下次成功启动建立新周期。归属进程组退出后取消，不等日志排空。取消退出确认不停止探测，确认退出才进入停止流程。

会话拥有配置快照、取消令牌、不可变探测快照及状态通知（状态、失败数、最近检查时间）。Core 拒绝取消后的结果；桌面回调执行时再次检查会话身份及运行版本，旧成功、失败或超时不能覆盖新运行。无探测的启动调用保持兼容。

### 显示与统计

命令列表、输出选择器、当前输出共用状态投影；停止、重启及退出结果优先。状态刷新不清空输出或影响选择、滚动。项目按唯一命令 ID 统计“X 个运行中，其中 Y 个探测通过”；X 包含活动任务与服务，Y 仅含当前 Passed 服务，多分组引用不重复计数。一键运行仍要求选择命令或已有分组。

探测状态只存在当前运行内存中，不改变历史日志格式，不插入 stdout/stderr。历史批次不显示当前探测结果。界面明确提示：TCP 可连接不代表业务健康，也不能确认监听者属于该命令。端口被另一程序预占也可能探测通过；不检查、接管或停止该监听者。

验收按[清单](acceptance-v0.3.0.md)先配置及 Core、再桌面、最后候选包进行；模拟时钟与连接器验证竞争条件，真实回环合成服务验证连接，不使用用户工作区。

## 分组执行原则

- 同时分组按保存的成员顺序发起命令，但不等待前一条完成；已占用成员被跳过，其余成员继续启动。任一成员运行失败时，TalosDesk 会停止由本次分组执行启动且仍在运行的其他会话，并显示失败命令、退出码与清理结果；不会停止手动启动、被该次执行跳过或后来重启、再次执行产生的新会话。
- 同时分组的任务完成通知与失败监视分开处理：任务全部成功后立即显示任务成功及继续运行的服务数量，但监视持续到本次启动的成员全部结束，或发现失败、任务被停止后进入清理。纯服务分组也持续监视；服务正常退出或被手动停止不会结束对其他服务的监视。旧执行的回调不得覆盖再次执行后的分组状态，失败清理按会话身份限定范围。
- 顺序分组启动前会预留全部成员，防止手动运行或其他分组抢占；前一条任务成功后才启动下一条。
- 顺序任务启动失败、非零退出或由用户停止时，剩余成员不再运行。停止当前命令即终止该顺序队列。
- 顺序队列活动期间不允许修改或导入工作区；查看输出、停止当前命令和导出配置仍可使用。
- 应用退出时先取消尚未启动的顺序步骤，再按既有进程归属规则停止当前实例已经启动的命令。

## 进程管理原则

- 只管理由当前应用实例启动并能可靠确认归属的进程。
- 停止时先向命令进程组发送 Ctrl+C，等待 5 秒；仍未退出时强制结束归属进程组并确认结果。
- Ctrl+C 发送期间用宿主自己的控制台处理器接收信号，并等待本机回调后解除附加；不设置可被后续命令继承的忽略标记。附加控制台会重置处理器表，须重新注册，依据 [SetConsoleCtrlHandler 文档](https://learn.microsoft.com/en-us/windows/console/setconsolectrlhandler)。连续启动与停止须保持优雅停止能力。
- 启动成功只表示进程已经创建；“运行中”不代表服务已就绪。
- stderr 仅表示进程写入了诊断通道，不代表命令失败；最终成功或失败以进程退出状态和退出码为准。
- 正常完成、执行失败和用户停止使用不同状态。
- 工作目录始终来自保存的命令配置，不依赖应用启动时的当前目录。
- 首版不提供完整交互终端；需要密码输入、REPL 或交互选择的命令应在外部终端运行。
- 命令编辑器的补全仅枚举当前运行目录、`PATH` 中符合 `PATHEXT` 的程序和环境变量名；不启动 PowerShell、不加载 profile、不执行补全脚本，也不提供 cmdlet 参数语义补全。

## 配置和隐私边界

当前源码的工作区 schema 版本为 4，默认保存在 `%LOCALAPPDATA%\TalosDesk\workspace.json`。项目路径、命令、用途说明、分组关系、普通环境变量及 TCP 探测策略以明文 JSON 保存。schema 1 文件会以无分组工作区载入，schema 1–3 文件在下一次成功保存时升级为 schema 4；读取不改写源文件。旧版本应用应拒绝 schema 4，避免忽略并覆盖新字段。下文 T02 保留历史 schema 3 的环境变量契约，schema 4 继续遵守其变量结构规则。

桌面快捷方式显式传入工作区文件路径；命令行也支持 `--workspace <文件>`，用于在不同 Windows 启动上下文中保持同一配置边界。

项目和命令 ID 必须为非全零 GUID，继续遵守各自的工作区全局唯一规则。schema 1–4 的读取、导入、保存与导出共用校验，遇到全零 ID 时以 `InvalidDataException` 拒绝，不改写原文件、不自动生成替代 ID。桌面加载失败时沿用错误提示与禁用保存流程；导入失败时不进入预览或合并。桌面启动入口再次检查项目与命令 ID，无效时在创建日志批次和目标进程前返回错误，不影响其他运行中的命令。

应用以规范化后的工作区绝对路径作为实例边界：同一路径只允许一个进程持有，重复启动会在没有命令运行或保存操作时先从磁盘重新加载工作区，再唤醒已有窗口；不同路径仍可并行打开。侧栏显示当前工作区身份、项目数量和配置路径，隔离测试通过 `--workspace` 和 `--profile-label` 明确传入测试身份，不再修改源码中的默认路径。工作区对象和内容摘要由同一次文件读取产生，避免文件替换时把旧内容与新摘要错误配对；检测到文件被外部程序改写时停止继续保存，并要求重新打开以加载新内容。

v0.2.0 已加入显式敏感环境变量的桌面编辑、DPAPI 本机存储、导出剔除、运行注入和输出脱敏。编辑器不会解密回填已保存值，并明确提示命令文本和普通变量仍是明文；用户不应把密码、令牌或 API 密钥直接写入这些字段。导出流程同样提示明文边界。

日志文件也是明文；新批次在写入前遮蔽本次运行已知非空敏感值及有限令牌模式，旧日志不会自动改写，目标程序另写的文件也不受处理。输出页显示实际存储路径和清理入口；日志设置保存在实际日志目录的 `settings.json`，位置记录保存在工作区文件旁，两者均不纳入工作区导入导出。自定义 `--workspace` 的日志和位置记录只属于该工作区，隔离测试使用独立临时目录。

## T02：schema 3 配置与交互契约（分批实施）

本节是 v0.1.1 T03–T05 的实施和验收约定。**T03 已实现文件结构、DPAPI 本机保存和安全导出；T04 已接入运行注入与输出脱敏；T05 已实现桌面编辑、完整导入预览和隐私提示。**字段名沿用现有 JSON 的 PascalCase；未列出的项目、命令及分组字段保持 schema 2 含义。敏感范围仅限显式标记的环境变量值，不自动解析或加密 `Command`、`Purpose`、路径、普通变量或旧日志。

### 文件形状与状态

每条命令新增必需的 `EnvironmentVariables` 数组，保留用户定义的顺序；schema 1/2 读取时将缺失字段视为 `[]`，读取本身不写回。schema 3 中缺少数组或数组为 `null` 属于结构错误。schema 3 的每一项恰有以下一种形状：

| 形状 | 必需字段 | 禁止字段 | 运行含义 |
| --- | --- | --- | --- |
| 普通值 | `Name`、`IsSensitive: false`、字符串 `Value` | `ValueState`、`ProtectedValue` | 原样注入；`Value: ""` 是显式空值 |
| 待填写敏感值 | `Name`、`IsSensitive: true`、`ValueState: "Required"` | `Value`、`ProtectedValue` | 阻止依赖该变量的命令启动，不读取同名继承值 |
| 已保护敏感值 | `Name`、`IsSensitive: true`、`ValueState: "Protected"`、非空字符串 `ProtectedValue` | `Value` | 启动前用 Windows DPAPI `CurrentUser` 解密后注入；解密结果可以是空字符串 |

`ProtectedValue` 是 DPAPI 输出字节的 Base64 文本，只存在于本机工作区和明确导入的本机备份中；不包含明文或可移植密钥。`Protected` 表示有密文，**不保证当前用户能解密**。Base64 损坏、DPAPI 拒绝或跨账户读取产生运行期“不可解密”状态：保留原密文字节和文件，提示重新录入，不把状态改成 `Required`、不使用旧值或同名继承值。缺少必需字段、出现互斥字段、重复变量名、未知 `ValueState` 或类型错误属于结构错误，读取或导入时整体拒绝，原文件不变；密文内容是否可解密留到启动前检查，不因损坏而抹去工作区。写入始终使用 schema 3；旧应用应拒绝 schema 3，而不能忽略环境变量后覆盖保存。

以下是**可分享导出**的合成样例。示例路径和命令只作占位，`API_TOKEN` 必须在目标机器填写后才能运行。真实本机文件在填写后，仅将该项的 `ValueState` 改为 `"Protected"` 并增加 `ProtectedValue`；绝不增加 `Value`。`Kind: 0` 沿用当前 JSON 中的任务命令枚举表示。

  "Projects": [

      "Id": "11111111-1111-1111-1111-111111111111",

### 校验、覆盖与编辑

- 变量名不能为空或全空白，不得以空白开头或结尾，也不得包含 `=` 或 NUL；保存和读取使用 `StringComparer.OrdinalIgnoreCase` 在**同一命令内**判重，不自动去空白或改大小写。值必须是字符串且不得包含 NUL；普通值和已保护敏感值都允许显式空字符串。敏感明文按 UTF-16 码元计最长 4096 个，超过时拒绝保存或启动；损坏的密文解密失败也拒绝启动。工作区路径、命令文本和环境总大小仍可能触发 Windows 启动失败，按现有启动错误处理。
- 每次启动从当前进程继承的环境建立独立快照，再按 Windows 不区分大小写的变量名覆盖。配置的普通空字符串覆盖同名继承值；`Required` 或不可解密的敏感项不回退到继承值。只给本次目标进程传值，不更改 TalosDesk 全局环境，不把秘密拼入命令行、状态文字或错误信息。未配置变量保留继承值；由外部环境带入的其他秘密不在本功能保护范围内。
- 编辑器对普通项显示并允许改写明文；敏感项只显示“待填写”“已保存”或启动检查后得到的“不可解密”，不回填密文解密后的明文。敏感项操作分为“保持原值”“替换值”“删除变量”；替换时显式空字符串也算新值。把普通项改为敏感项需明确选择以当前值加密或重新填写；把敏感项改为普通项必须重新输入普通值，绝不自动解密回填。敏感项改名等同删除旧项并新增待填写项，除非用户同时提供新值。取消、关闭编辑器或保存失败均保留此前工作区与原密文；保存成功才替换。编辑器提示命令文本和普通变量仍是明文。
- schema 1/2 升级只在下次成功保存时进行，使用工作区已有的原子替换和外部改写检测；失败保留原文件并清理临时文件。不自动额外备份旧工作区，因为其中可能已有明文秘密。需要手工备份时，由用户选定安全位置并知晓旧文件、命令文本及旧日志可能仍含明文；恢复 schema 3 应使用支持 schema 3 的应用，不让旧版降级写回。

### 导出、导入和冲突

- 导出先构造独立深复制投影，普通变量和其他非敏感字段照原样保留；**所有**敏感项均变成 `ValueState: "Required"`，不含 `ProtectedValue`，无论本机原状态是已保护、待填写或不可解密。导出不改变内存对象或本机工作区，不允许以当前工作区文件为导出目标，写失败不损坏已有目标文件。导出前继续警示路径、命令文本、用途和普通变量可能含明文；预览不显示密文或秘密。分享前仍需人工检查这些未受保护字段。
- schema 1/2/3 文件均可导入，且导入前必须展示项目、命令、分组及敏感变量名和状态的预览，不执行任何命令。导入的 `Required` 保持待填写；导入的 `Protected` 密文原样保留，预览仅标注“本机密文、可用性未验证”，不在预览时解密或复制到可分享导出。由另一账户带来的密文可能在启动检查时报告不可解密。
- 同一项目、同名命令继续按现有冲突选择处理。预览及命令冲突对话框须指出本机和导入项各有多少敏感变量、选择替换将以导入项**整套**变量为准，并可能让原来可运行的命令变为待填写或不可解密。选择“保留本机命令”同时保留原变量和密文；选择“替换”不按同名变量隐式沿用旧密文；取消不改变工作区。新增命令携带导入的整套变量。合并时深复制数组及项，重映射命令 ID 不改变变量数据；整个导入保存失败时恢复原工作区。旧 schema 无变量的命令若覆盖同名命令，也明确清空其旧环境变量。

### 启动与输出失败边界

- 单条运行或重启，在创建日志批次或目标进程前验证所有变量，并完成本次所需的 DPAPI 解密；`Required`、不可解密、超长值或无效配置直接失败，提示命令及变量名但不包含值、密文或底层异常原文。顺序分组先检查全部成员，成功后才预留；同时分组只检查本次空闲、实际会启动的成员。任一成员有已知配置错误，**整次分组不启动任何成员**；勾选多条命令批量运行也按实际空闲成员先整体检查。顺序分组逐步启动时重新取值，若此前检查之后配置可用性变化，则终止后续队列；同时分组通过检查后的进程创建失败沿用现有失败报告与清理规则。预检不创建日志批次，也不改变已在运行的命令。
- 本次运行的已知非空敏感值在 stdout、stderr 各自的字符流中精确匹配并替换为 `[已隐藏]`，然后才按行分发给实时界面、内存、复制、磁盘日志和诊断；不跨两个通道拼接。显式空敏感值没有可匹配字符。最小补充模式覆盖 `Bearer <token>` 和 `token=` / `api_key=` 后的非空非空白值，忽略 ASCII 大小写；模式命中时保留字段名并隐藏值。秘密值匹配区分大小写，模式匹配有明确超时和长度边界，不承诺识别编码、拆到两个通道或目标程序另写文件中的值。
- 输出按每通道最多 16,384 个 UTF-16 码元的处理块送入脱敏器；跨块及跨行只保留仍可能构成敏感值或模式前缀的后缀，残片上限 4,095 码元。模式候选超过 256 码元时，从其可识别前缀起持续省略到分隔符，不缓存无界令牌；每块模式匹配超时为 50 毫秒。超时、超限或其他无法确认安全性的片段整段省略，向该通道输出固定的 `[已省略：脱敏失败]` 提示，绝不回退原文或把原异常写入备用日志。正常结束、停止和读取异常时，都先按同样规则处理残片再关闭该通道；若无法安全完成则省略残片。既有历史日志不自动改写，旧文件可能仍含秘密，沿用现有路径提示与清理入口。

### 版本来源与候选选择

- 本机版本读取程序集 `InformationalVersion`，构建渠道由明确的 `ReleaseChannel` 元数据给出，值为 `Stable` 或 `Preview`。v0.2.0 没有 SemVer 预发布后缀，稳定发布构建元数据明确写入 `Stable`；不能由版本字符串或远端联网结果推断本机渠道。缺失、重复或无效的版本/渠道元数据使检查不可用并显示本机版本信息异常，不猜测渠道或触发自动联网。
- 远端标签接受可选的单个小写 `v` 前缀，其余必须满足 [SemVer 2.0.0](https://semver.org/)。比较数字主次补丁及预发布标识，忽略构建元数据，不按字符串、发布日期或 API 返回顺序比较。示例：`0.2.0-preview.2 < 0.2.0-preview.10 < 0.2.0 < 0.10.0`；`v0.2.0+build.1` 与 `0.2.0` 等价。
- 读取 [GitHub Releases 列表](https://docs.github.com/en/rest/releases/releases#list-releases)，不使用 `/releases/latest`。排除 `draft: true`；仅稳定版同时排除 `prerelease: true` 和有 SemVer 预发布后缀的版本；包含预览版则接受两种渠道。只返回严格高于本机的最高合格版本；同版本重发、修改标题、转为稳定版或增加附件都不触发更新，发布更改需使用更高版本才能被提示。
- 不符合 SemVer 的完整发布记录不参与候选；必需字段 `tag_name`、`draft`、`prerelease`、`html_url` 缺失或类型错误属于异常响应。合格版本的发布链接校验失败也使本次检查失败，不能绕过它回退到更旧版本并宣称最新。同优先级候选先选稳定标志，再按原始标签的 ordinal 顺序选取，保证结果确定。
- 完整检查中无合格发布时显示“当前渠道暂无可用发布”；有合格发布但都不高于本机时显示“当前渠道没有更新版本”。检查失败、仅有历史缓存或分页不完整时不得显示“已是最新版本”。

### 请求、限流与发布链接

首次请求固定为 [官方仓库 Releases API](https://api.github.com/repos/kongerly/TalosDesk/releases?per_page=100&page=1)。使用匿名 GET、`Accept: application/vnd.github+json`、固定产品标识 `User-Agent: TalosDesk` 和明确的 API 版本头 `X-GitHub-Api-Version: 2026-03-10`。不读取 GitHub 登录凭据，不发送 Authorization、Cookie、工作区路径、项目、命令、日志、环境变量或持久设备标识。采用系统代理与正常 TLS 校验，不增加代理设置或绕过证书验证。

- 每页最多 100 条，通过 `Link` 的 `next` 分页串行读取。下一页必须仍为 HTTPS、`api.github.com`、同一仓库 Releases 路径，只允许固定 `per_page=100` 和递增 `page` 参数，不带用户信息、异常端口或片段。拒绝循环、重复或不合法分页链接，不访问其他地址。
- 每次检查最多 5 页，从首次请求到全部读取解析完成共用 15 秒预算；读取的响应正文按解压后字节累计，最多 5 MiB，不只信任 `Content-Length`。超过预算、页数或响应量立即结束为“未完成检查”；第 5 页仍有 `next` 也属于未完成，不公布部分列表的新结论。
- 禁止自动跟随 HTTP 重定向。固定地址返回重定向时显示更新源地址异常，后续仓库迁移由维护者修改受信地址；不自动接受新的仓库或主机。这是固定更新源的产品约束。
- 每次检查的首次请求之间至少间隔 60 秒，检查内的分页请求不受此间隔限制。403/429 限流时遵守有效的 `Retry-After`；`X-RateLimit-Remaining=0` 时同时考虑 `X-RateLimit-Reset`，取最晚允许时刻。无有效等待头时至少等待 60 秒。等待期限同时限制手动和自动检查，不在后台自动重试，页面显示何时可再试。条件请求及限流依据见 [GitHub REST API 请求建议](https://docs.github.com/en/rest/using-the-rest-api/best-practices-for-using-the-rest-api)。
- 只有用户点击才用系统默认浏览器打开候选 `html_url`。解析 URI 并要求 HTTPS、主机精确为 `github.com`、默认 HTTPS 端口、路径精确为 `/kongerly/TalosDesk/releases/tag/<该候选合法标签>`；标签作为单一路径段匹配，拒绝路径穿越、额外路径、用户信息、查询参数或片段。读取缓存和打开前均重新校验，不能只判断字符串前缀。
- 不请求附件、执行脚本或内嵌网页，不渲染远端标题/正文或加载其图片。页面显示经校验的版本及渠道，发布说明留在浏览器查看。浏览器后续请求由浏览器负责，不声称能约束页面内导航。

离线、代理/TLS 失败、超时、404、服务器错误和异常响应均归为可理解的页面状态，后台失败不弹窗。错误文案使用固定类别，不展示或另存响应正文、代理地址、请求头或底层异常原文。浏览器打开失败只显示页面提示，不影响正在运行的命令。

### 工作区隔离、缓存与保存失败

两个 JSON 文件都以规范化工作区文件路径加后缀定位，字段使用 PascalCase，各自从独立 `SchemaVersion: 1` 开始；这不是工作区 schema 的升级。只在需要保存偏好或实际检查记录时创建文件，默认关闭且未操作时不写更新文件。

| 文件 | 必要内容与用途 |
| --- | --- |
| `<工作区文件名>.update-settings.json` | 自动检查开关（默认 false）、渠道选择（默认 `FollowCurrent`）、已跳过版本集合及按版本保存的稍后 UTC 期限 |
| `<工作区文件名>.update-cache.json` | 上次实际尝试/成功时间、限流等待期限；上次完整成功结果的逐页请求地址、ETag、分页信息和未经渠道过滤的 `tag_name`、`draft`、`prerelease`、`html_url` 投影，不保存原始响应或发布正文 |

- 文件不进入工作区读写、导入、导出或配置冲突合并；`--workspace` 自然隔离两个文件，不另设用户全局更新配置。两个工作区即使属于同一用户，也分别保存偏好和缓存；不承诺跨工作区合并请求，共享出口限流按响应处理。
- ETag 与完整请求地址、请求头版本和该页内容绑定；304 只能复用匹配且通过校验的页缓存，同时使用其分页信息。始终先取得未按渠道过滤的完整列表，再按当前渠道筛选。没有对应有效缓存的 304 属于检查失败，不凭空补空列表或自动重试。
- 一次检查的页集合在全部成功后才整体替换旧集合；失败保留上次完整结果，同时保存新的尝试时间和限流信息。时间及页面内容在同一缓存文件内原子写入，不能把新 ETag 与旧页内容拼接。网络失败只显示带原成功时间的历史结果及本次失败状态，不因新尝试时间而把旧结果显示为新结果。
- 自动检查在 24 小时内被节流时不以旧缓存补发提示；历史结果仍可在更新页查看。24 小时只控制自动请求频率，不代表缓存仍是最新结果；不另设缓存有效期，未经本次完整检查（200 或有效 304）验证的缓存一律只作带时间的历史展示。系统时间回拨或缓存时间落在未来时，普通频率记录作失效处理，不无限延后检查；有效的服务器限流期限仍应遵守。同一会话的最短请求间隔使用单调时钟。
- 两文件分别采用同目录临时文件和原子替换，失败保留原文件并清理临时文件。网络判断成功而缓存保存失败时，本次结果仍有效，显示“检查完成，记录未保存”；本次会话仍遵守频率和限流，不因写失败循环请求。
- 正常偏好修改先作用于本次会话；写失败则显示“设置未保存，重启后可能恢复原设置”。关闭自动立即生效，即使磁盘上仍为开启，也不能在本次会话继续自动检查。该提示同样适用于渠道、跳过和稍后记录。
- 偏好不存在时用默认值；损坏、不可读或未知格式时保留原文件，自动检查关闭，禁用偏好修改，手动检查使用跟随当前版本渠道。页面显示实际文件路径，并说明关闭应用后保留并移走异常文件、重新打开即可恢复，不静默覆盖或自动生成备份。缓存损坏只放弃缓存内容，不重置偏好；缓存不可写仍允许手动检查。
- 关闭应用后可单独删除缓存，下一次检查重新读取元数据；删除偏好会恢复默认关闭和默认渠道，并清除跳过/稍后记录。两个文件都不含凭据，但检查时间和提醒记录是本机使用信息，不纳入发布包。

同一工作区实例仅保留一个检查任务，重复点击合并，不并发请求。手动检查接管正在运行的自动检查后，该任务归为手动，结果按手动规则展示，不再受跳过/稍后抑制；关闭自动不取消用户等待中的手动任务。

确认退出时取消延迟任务和所有请求，关闭 HTTP 资源，不等待网络完成、不延长原有进程退出流程。用户在既有退出确认中选择返回应用时，不视为已确认退出。更新模块不停止、重启、预留或接管任何命令；包括工作区没有项目、命令运行中或用户正在看输出时，更新页和异步请求都不能阻止原有操作。

手工升级说明随功能实现同步到 README 和包内说明：从发布页下载完整便携包并校验，停止命令、退出应用，备份本机工作区及所需旁文件后再更换应用目录；不要覆盖正在运行的程序。工作区数据保留在原位置，新旧包使用明确的同一 `--workspace` 路径。跨版本回退使用旧版兼容的配置副本，不能让旧包覆盖较新 schema；可分享导出不保留敏感值，不能代替本机完整备份。T07 不新增备份或回滚执行功能。

## T08：v0.2.0 本地崩溃诊断契约（已实现）

本地诊断按工作区默认开启，记录目录为 `<工作区文件路径>.crashes`，开关文件为 `<工作区文件路径>.diagnostics-settings.json`。两个边界使用独立 schema 1，不修改工作区 schema 3，也不进入导入导出。关闭只影响后续采集，既有记录由用户在“关于与更新”页查看或清理。

每条记录只保存随机 ID、UTC 时间、应用版本和渠道、Windows/.NET/架构、异常来源、致命标记、异常类型、HResult，以及只含可信程序集类型和方法名的结构化堆栈。磁盘字段保持 UTC，记录列表与详情按当前 Windows 本地时区转换，页面明确说明时间来源，不修改历史文件。不读取或保存异常消息、`ToString()`、`Data`、源码路径、用户名、工作区、命令、输出、环境变量或凭据；外部和动态元数据使用固定占位符。

记录最多 8 个异常节点、4 层、每节点 32 帧、字符串 256 字符、单文件 64 KiB；每工作区最多 100 条、5 MiB、30 天。启动查看和写入前先清理过期记录，再从最旧记录清理容量。只管理规定名称的顶层 JSON 和临时文件，不递归、不跟随重解析点。损坏或未知格式显示固定状态，不展示原文，但仍计入容量并可清理。

UI Dispatcher 与 AppDomain 未处理异常通过无等待重入保护至多写入一次，随后以非零状态退出；不继续操作工作区或进入普通退出确认。未观察任务异常每会话最多记录一次且不改变运行时策略。投影、写入、读取或清理失败返回固定状态，不保存底层异常原文、不换目录、不自动重试，也不为记录器失败生成递归记录。

“关于与更新”页显示开关、实际目录、数量与容量、记录列表、只读最小详情、刷新、打开目录及确认后清理入口。诊断不自动上传或创建 issue。参数解析前、强制结束、断电、栈溢出、严重内存故障及文件系统阻塞可能没有记录；应用策略不控制 Windows 自身错误报告。
