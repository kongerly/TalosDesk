# TalosDesk 设计说明

本文记录当前源码的行为契约，写给需要修改代码、核对行为或评审改动的人。它按主题列出现行规则，不按操作步骤编排；只想使用 TalosDesk 的读者可以先看 [README](../README.md) 和[常见问题](faq.md)。版本与交付状态见[路线图](roadmap.md)，数据位置与清理见[隐私说明](privacy.md)，检查方法见[测试说明](testing.md)。历史发布不自动具备当前源码的能力。

## 产品与技术范围

TalosDesk 是单用户、Windows 本地的非交互命令运行工作台。核心流程是：选择项目、运行命令、查看结果、停止或重启。

技术栈为 C#、.NET 10、WPF 和本地 JSON。PowerShell 7 由用户自行安装，核心运行不依赖后端或模型 API。SDK 由 `global.json` 固定，自包含运行时由 `eng/dotnet-sdk.json` 固定。

`TalosDesk.Core` 负责配置、进程、分组、日志、探测、恢复、更新和诊断。`TalosDesk.App` 负责 WPF 交互，以及 Windows 窗口、托盘和实例协调。编辑控件使用 AvalonEdit，第三方版本见项目文件及许可声明。

## 命令与进程

默认使用 `pwsh -NoProfile -NonInteractive -Command` 执行保存的命令，也可选择下述 Windows Cmd；工作目录来自配置。PowerShell 编辑器的补全只会枚举目录、`PATH`、`PATHEXT` 和环境变量名，不会执行输入内容，也不会加载 profile。

根进程先以挂起状态创建，加入独立的 Windows Job 后再恢复执行。应用只管理本次启动且能确认归属的进程，不会按进程名批量结束。

归属 Job 的进程列表以 128 项作为初始容量；遇到 `ERROR_MORE_DATA` 或返回数量少于所需数量时，扩大缓冲并重查同一 Job，取全后再用于退出判定。每次查询的非托管缓冲均释放，其他查询错误仍报告，不能把失败或截断列表当作空进程组。列表是当时的快照，遵循 [Windows Job 进程列表接口规则](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_basic_process_id_list)。

停止时先尝试 Ctrl+C；等待 5 秒仍未退出，就终止归属 Job 并确认结果。Ctrl+C 能否送达取决于控制台和目标处理器；宿主自身的信号处理不能把忽略标记传递给后续命令。

进程存活、TCP 可达、正常完成、非零失败和用户停止是五种不同状态，分别显示。stderr 只是诊断通道，最终结果按退出状态判断。捕获输出前会先关闭 PowerShell 的 ANSI 样式。

同一条命令不能重复运行。如果创建回滚或观察失败，只要尚未确认归属已释放，就保留占用状态和停止入口。`Completion` 完成或抛错都不等于归属已经释放。

停止已确认 Job 退出，而观察恰好在停止锁持有期间失败时，观察收尾在锁释放后仍须排空输出并释放归属，无需用户再次停止。原始观察异常仍向调用者报告；尚未确认退出的故障继续保留占用和控制资源。

### Windows Cmd

首版仅支持 Windows 系统目录中的 `cmd.exe`、非交互单行命令，最多 7,000 个 UTF-16 码元（为 Cmd 本身及引导参数保留空间），拒绝换行和 NUL。复杂流程写入 UTF-8 批处理文件，再显式调用，例如 `call "脚本 空格.cmd" "参数"`。含空格或特殊字符的路径和参数使用 Cmd 的双引号/转义规则；变量用 `%NAME%`。不会翻译 PowerShell 语法，不扩展 Git Bash、WSL 或交互式终端。

实际解释器使用 `/d /q /e:on /v:off /s /c`：禁用 AutoRun、关闭回显、开启命令扩展、默认关闭延迟变量展开。引导层先调用系统 `chcp.com` 设置独立控制台为 65001，再启动实际解释器，避免本机观察到的同一行切换代码页后仍缓存旧编码的问题。引导层仅通过随机名称的进程环境变量延迟展开一次传入原始命令，避免额外解释引号、`&`、`%` 和 `!`；该内部变量会由子进程继承。不写临时命令脚本，不修改宿主全局环境；引导与实际解释器都在恢复执行前归属同一 Job。

stdout/stderr 均按 UTF-8 解码，保留 Cmd 原始空格与换行。使用 UTF-8 的 Cmd 内建命令、UTF-8 批处理和原生程序已覆盖隔离测试；自行输出 GBK/OEM、UTF-16、二进制或主动修改代码页的工具，需要自行配置 UTF-8，不自动猜测混合编码。`/u` 会让内建输出与原生工具输出混用编码，因此不启用。控制规则仍为先 Ctrl+C、5 秒后强停归属 Job；不接管其他控制台或进程。Cmd 编辑器只提供普通文本，不套用 PowerShell 着色、补全、成对输入和多行缩进。

引用及代码页规则参考 [Microsoft Cmd 文档](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/cmd)和 [chcp 文档](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/chcp)；产品范围以本段和隔离测试为准。

## 分组执行

分组属于项目；同一条命令可以被多个分组引用，每个分组里的成员各自保存顺序。

| 模式 | 启动与结束规则 |
| --- | --- |
| 同时执行 | 按顺序发起空闲成员，跳过已被占用的成员。任务全部成功后可以提示任务完成，但仍继续监视服务，直到本次成员全部结束 |
| 按成功顺序执行 | 只允许任务。启动前预留全部成员；前一项成功后才启动下一项，失败、停止或启动失败都会终止队列 |

同时执行的组里只要有成员失败，应用就只停止本次启动、且身份仍匹配的其他会话。被跳过的独立服务、恢复轮次和后来新建的会话都不会被接管，旧执行的回调也不能覆盖新执行。顺序队列活动期间禁止修改或导入工作区；退出时先取消未启动的步骤，再停止归属会话。

批量启动命令时，先对实际成员做整体预检；只要发现已知配置错误，整批都不启动。预检之后的创建或执行失败，仍按归属规则处理。预检本身不创建进程，也不写日志批次。

## 工作区与保存

当前源码保存 schema 6，可以读取 schema 1–5。读取不会改写文件，只有下一次成功保存才升级；旧应用会拒绝不支持的 schema。schema 2 加入分组，3 加入环境变量，4 加入 TCP 探测，5 加入自动重启，6 加入命令 `Shell`：缺省/0 为 PowerShell，1 为 Cmd，保存默认值时省略。旧 schema 出现 Shell 字段、null、非整数、越界、重复键与大小写变体均拒绝。编辑、复制、导入预览及冲突替换和导出保留 Shell；读取和导入都不运行命令。示例见 [examples](../examples/README.md)。

- JSON 字段使用 PascalCase。所有对象都拒绝未知字段、重复键、大小写变体和错误类型，也拒绝非法的必需值，统一以 `InvalidDataException` 表达。应用不会静默丢弃字段，也不会覆盖原文件。
- 项目和命令 ID 必须是非全零 GUID，并满足各自的工作区全局唯一规则。错误的 ID 不会自动重新分配。
- 同一规范化工作区路径只允许一个实例。再次启动时，如果应用空闲且没有保存操作，会先重载磁盘，再唤醒窗口。`--workspace` 和 `--profile-label` 明确配置边界与界面身份。
- 内容和基线摘要来自同一次读取。保存时在锁内规范化副本，用同一份 UTF-8 字节写临时文件并返回摘要，替换前再核对预期摘要。失败时保留调用方对象和原文件，并清理临时文件。
- 首次创建时禁止覆盖外部新建的文件。已有文件在替换前必须关闭最终校验用的只读共享句柄，因此仍有一个极短的竞争窗口；这个保护不构成跨程序的文件系统事务。
- 外部变化会禁用保存并取消恢复轮次。激活后的异步检查必须核对原基线和当前保存/重载状态，忽略迟到的结果；保存层的最终校验独立执行。
- 编辑和确认的模态窗口会阻止延迟重载。编辑开始时捕获确切对象，保存前重新核对归属、索引和占用，不能因为选择变化就把草稿写进另一条命令。

工作区保存替换文件时，Windows 错误 5/32 可能是短暂拒绝。若本次临时文件仍存在，最多追加 5 次尝试，分别等待 20/40/80/160/200 ms；复用同一路径和已序列化字节，每次替换前重新校验预期摘要及取消状态。外部修改、首次创建冲突或取消会中止，其他错误立即报告，持续拒绝仍会失败并尝试清理临时文件。设定等待累计 500 ms，不含调度和文件系统调用时间；具体占用来源未确认。

导入时先展示完整预览和冲突范围，确认后只保存，不执行也不探测。保留本机项时保留整套配置；替换时使用导入项的整套变量、探测和恢复开关，不隐式沿用旧密文。合并会深复制配置，失败时恢复原工作区。

导出会把敏感项转为待填写，并拒绝覆盖当前工作区，以及目录联接、符号链接别名；同卷手工硬链接仍无法识别。回退要使用旧版兼容副本，可分享导出不能代替完整备份。

## 环境变量与脱敏

schema 3–6 的每条命令都必须包含非 null 的 `EnvironmentVariables` 数组；schema 1/2 缺失该字段时按空数组读取。

| 形状 | 必需字段 | 禁止字段 |
| --- | --- | --- |
| 普通值 | `Name`、`IsSensitive: false`、字符串 `Value` | `ValueState`、`ProtectedValue` |
| 待填写敏感值 | `Name`、`IsSensitive: true`、`ValueState: "Required"` | `Value`、`ProtectedValue` |
| 已保护敏感值 | `Name`、`IsSensitive: true`、`ValueState: "Protected"`、非空 Base64 `ProtectedValue` | `Value` |

变量名不能是空白，不能首尾带空白，也不能含 `=` 或 NUL；同一条命令内按不区分大小写判重。值不能含 NUL；普通值和解密后的敏感值允许空字符串，敏感明文最多 4096 个 UTF-16 码元。密文无法解密时，应用保留原数据并阻止启动，不会回退为继承环境或空值。

每次启动都会建立独立的环境快照并覆盖继承值，只注入目标进程，不修改宿主的全局环境。DPAPI 使用 `CurrentUser`；编辑器不会解密回填，改名或改为普通项都需要重新提供值，取消和保存失败都保留原配置。

stdout/stderr 会先脱敏，再进入界面、内存、复制和磁盘。脱敏会精确遮蔽本次已知的非空敏感值，并补充有界的 `Bearer`、`token=`、`api_key=` 模式。处理块最多 16,384 个 UTF-16 码元，可能匹配的后缀最多保留 4,095 个；模式值持续省略到空白分隔符，不缓存整个值，单块处理超时 50 ms。遇到超时、超限或残片无法安全处理时，输出固定省略提示，不回退原文。

已脱敏的超长单行按每条最多 16,384 个 UTF-16 码元分段发布；边界上的高代理项保留到下一段，避免将有效代理对拆到两条独立编码的记录中，导致 emoji 或扩展汉字落盘后变成替代字符。分段位置按脱敏后的长度决定，适用于两个输出通道。

同一行已发布完整分段时，紧随的 LF 或 CRLF 只结束该行，不追加空记录；真实的连续换行仍保留空行。边界上的回车保留到下一次处理，再与 LF 一起规范化，避免回车残留在分段正文；流结束时没有 LF 的单独回车仍保留在输出记录中。

脱敏失败时，输出泵在继续读取前将固定提示作为完整的独立记录发布，不等待换行或流结束；此前已脱敏的半行先单独发布，提示不会在 16 KiB 边界被拆开。失败通道继续排空输入并省略后续原文，同一次失败不因流结束或后续读取异常重复提示。读取异常也只发布固定提示，不暴露异常原文；正常半行仍按原有换行、长度上限或流结束规则发布。

匹配已知敏感值后，仍逐字符检查已遮蔽区域；从其内部开始的其他已知值会扩展遮蔽范围，重叠命中合并为一段，不能跳过内部开头而暴露后缀。跨块只保留可能匹配的后缀和剩余遮蔽长度，不积累整条重叠链。

已知值与模式前缀在每个输入位置独立匹配。命中前缀后仍逐字符处理，到前缀末尾才启用后续值的省略；前缀各字符也参与已知值脱敏。已知值遮蔽区和已有令牌省略区中的新前缀同样有效，不能因为一种匹配覆盖了另一种的开头而漏掉其后缀。

令牌模式的省略状态也继续检查已知敏感值，跨块时保留可能的开头；模式值内部的已知值包含空格、制表符或换行时也完整遮蔽，不能在第一个空白处停止后暴露其余片段。已遮蔽的空白结束该令牌省略状态，已知值及其重叠范围继续遮蔽，之后恢复处理普通文本。

脱敏不处理旧日志、目标程序另写的文件、编码后的秘密，也不处理跨通道拆分的值。明文与 DPAPI 的保护边界见[隐私说明](privacy.md)。

## TCP 探测

只有服务可以配置 `TcpProbe`。字段缺失或为 null 表示关闭，保存关闭项时会省略该字段。非空对象必须完整包含下列字段；schema 1–3 拒绝非空探测。

| 字段 | 默认值 | 范围 |
| --- | --- | --- |
| `Address` | `127.0.0.1` | 精确为 `127.0.0.1` 或 `::1` |
| `Port` | 必填 | 整数 1–65535 |
| `IntervalSeconds` | 2 | 整数 1–60 |
| `ConnectTimeoutSeconds` | 1 | 整数 1–60 |
| `StartupTimeoutSeconds` | 120 | 整数 1–3600，且不小于连接超时 |
| `FailureThreshold` | 3 | 整数 1–100 |

| 状态 | 含义 |
| --- | --- |
| `NotConfigured` / `Inactive` | 未配置 / 未探测；停止失败且进程存活时显示探测已停止 |
| `Waiting` | 尚无成功且未到启动期限 |
| `Passed` | TCP 可达；阈值内失败仍保留通过并显示失败计数 |
| `TimedOut` | 首次成功前已超过启动期限，继续探测 |
| `Unreachable` | 曾成功，随后连续失败达到阈值；继续探测并可恢复 |

会话创建后立即尝试连接；每次结束再等待间隔。同一会话不会并发探测，也不补发；启动期限独立计时。连接成功即关闭，不发送业务数据，并清零失败数。首次成功之后不再使用启动期限。主动取消不计入失败。

停止请求或归属进程组退出时立即取消探测，不等日志排空。新会话会建立新周期，旧回调必须核对身份。探测失败不改变进程结果，不触发分组清理或自动重启。项目按唯一命令统计活动会话数和当前处于 Passed 的服务数；结果只存在内存里，不写历史日志。TCP 连通不能证明业务健康或监听者归属，不能据此接管其他监听者。

超时通知的订阅者若同步停止探测，发出通知的结果处理也会重新检查活动状态，不能继续发布该次连接结果、累计失败或更新检查时间。未被取消的迟到成功仍可从启动超时恢复为通过。

## 有限自动重启

schema 5 起的 `AutoRestartEnabled` 是服务的布尔开关，默认 false，保存 false 时省略。它拒绝 null、错误类型、任务上为 true，以及旧 schema 中的新字段。旧配置默认关闭；编辑、复制和导入导出都会保留该开关。

只有独立启动（单条或勾选批量）的服务，在 `Completion` 正常返回失败且退出码非零后才会恢复。每轮最多追加 3 次，等待 2/4/8 秒。任务、退出码 0 的服务、分组启动、TCP 失败和日志故障都不会触发。每次新会话都有独立的 Job、日志批次、运行版本和探测周期；旧会话的归属退出、输出和日志收尾完成后，才开始退避。

等待本身不消耗次数。到期并通过预检后，才在串行提交入口计次并创建。预检或创建失败会立即中止本轮；创建失败会消耗该次尝试。运行时长和 TCP 通过都不会重置次数。只有新的手动运行/重启成功，才会获得新预算。次数、截止时间和轮次只存在内存中，不跨启动恢复。

`CommandRecoveryCoordinator` 统一承接桌面的各个启动来源，创建/登记与停止/关闭共享同一条串行边界；桌面与 Core 公共入口都按每次预检计划中的 Shell 创建初次及重试会话。命令 ID、轮次和会话版本用来隔离旧回调，每条命令最多一条恢复链。如果观察或创建回滚时无法确认归属已释放，就保留故障占用；手动、批量与分组都不能绕过它。只要仍有控制资源，就允许再次停止。

停止或手动重启会先取消旧轮次；停止或重启的预检失败也不会恢复旧等待。等待、提交、收尾和故障归属都参与编辑/删除、导入/重载、日志迁移和退出保护。等待不计入运行数或 TCP 通过数，而是单独展示待重试数量。上一批次的真实退出码会保留；恢复状态不写入 stdout/stderr 或历史字段。

退出时先暂停自动提交，再读取包含待重试和未完成回调的快照。返回应用后保留原截止时间和预算，已到期的最多提交一次。确认退出会在首次异步等待前关闭所有启动入口并取消轮次，只等待已提交的归属会话停止和日志收尾，不等待退避。停止失败时保留窗口和停止入口，旧轮次不会恢复。最小化、切页和恢复窗口都不改变预算。

每次自动预检都从 Dispatcher 取得配置副本，重新验证工作目录、磁盘身份和敏感值；后台不访问绑定对象。保存期间暂停自动提交，结束后保留原截止时间。外部修改会取消轮次并禁用新启动。导入预览会明确开关、固定预算以及分组不生效；读取或确认导入都不会运行或探测。

## 日志存储与历史读取

日志按项目、命令、批次 GUID 分层，stdout/stderr 分开保存；元数据包含时间、结果以及截断/失败状态。重开时，未结束的批次记为中断。默认每个工作区 500 MB、保留 30 天；先清理过期批次，再按时间删除最旧的已结束批次。活动批次受内存 ID 保护，不会因为元数据损坏而被删除；如果只剩活动批次且容量不足，应用停止后续落盘并提示，命令继续运行。

目录枚举会跳过非 GUID 目录和重解析点。损坏、缺失或身份不符的 `run.json` 不会列入历史，但仍计入容量并可清理；排序和期限回退为目录的 UTC 修改时间。“清空显示”不删除文件，删除命令也不会立即删除历史。

手工清理、保留期及启动前轮转可能在部分删除后遇到文件占用而失败；错误仍向调用方报告，已经完成的删除不会回滚。删除失败后重算现存批次容量，避免已删除字节继续占用额度并阻止活动批次写入。若重算也受阻，保留原有保守计数，后续落盘仍可能受限；容量不足时仍按截断规则处理。

本次持有的活动批次在收尾时若发现 `run.json` 丢失，会先重算现存容量，再尝试用本次状态重建完成记录，保留结果、退出码、截断及写入失败标记，避免丢失的旧元数据被重复计入容量。恢复仅使用本次仍持有的状态；既有历史仍按损坏元数据规则处理。整个批次目录已丢失或写入仍失败时标记不完整，不重建已经丢失的输出。

收尾会分别尝试关闭 stdout 和 stderr 日志流。一项关闭遇到 IO 或权限错误时，标记日志写入失败并继续关闭另一项、释放本批次的活动保护，再尝试保存真实结果；重复收尾不再次关闭或覆盖结果。关闭失败不保证恢复未刷新的输出，后续元数据保存、迁移或清理仍可能因文件系统故障失败。

桌面收尾同时检查异常和日志写入失败标记。完成记录无法保存时，当前显示仍提示“日志完成写入失败。”；已有的本轮日志警告会保留。日志警告与命令结果分别展示，不改变真实退出码，也不单独触发自动重启；成功建立新的运行批次后清除旧轮次警告。

迁移日志要求没有活动批次或待重试。应用先迁移设置和历史，再切换位置，并拒绝覆盖已有目标。Windows 刚复制完嵌套目录时可能短暂拒绝重命名；暂存目录提交只对错误 5/32 最多重试 5 次，总等待不超过 500 ms，期间出现目标即停止重试。持续失败时保留原位置和日志，清理暂存副本，不切换位置记录。旧目录删除失败时会提示残留路径。

历史读取在后台按长度快照从尾部扫描最近 10,000 行，按 16 KiB 分块，支持 UTF-8 和 LF/CR/CRLF。磁盘读取和解码不持有日志写入锁，允许并发追加与删除。切换批次、通道、项目或关闭时取消旧请求，回调会再次核对身份；超长单行仍须读取全部字节，文件系统调用和 WPF 排版不能保证立即取消。

### 当前日志搜索

运行输出页的“查找”或 Ctrl+F 打开搜索栏。关键词按字面、忽略大小写匹配，支持中文、匹配高亮、计数、上一个/下一个循环导航；输入框内 Enter/Shift+Enter 导航，Esc 关闭。范围说明始终标出当前显示或所选历史批次、标准输出或诊断输出，以及最近 10,000 行。当前显示仍同时列出两通道，搜索只匹配“日志历史与设置”中所选通道；历史仅搜索该批次所选通道的已加载内容。

搜索只读取已脱敏的显示文本快照，不解密、不访问磁盘或建立跨批次索引，不修改 schema。后台搜索采用取消和请求版本校验，合并实时追加请求；高亮仅绘制可见行和可见字符范围。文本变化、切换命令/项目/批次/通道和清空显示立即清除旧匹配及当前位置，保留关键词并重算；清空显示不删历史。搜索结果不会自动滚动，导航时才选中并滚入匹配位置。已有大文本的 WPF 排版及显示快照复制仍在 UI 线程，不承诺超长单行的固定响应时间。

## 更新检查

本机版本来自 `InformationalVersion`，渠道来自明确的 `ReleaseChannel`（Stable/Preview）。缺失或无效时禁用检查，不猜测渠道。远端标签接受一个小写 `v` 前缀，按 SemVer 比较并忽略构建元数据。草稿会被排除；稳定渠道还会排除预发布标记与后缀。应用只提示严格更高的最高合格版本。

- 默认关闭。打开页面、切换渠道以及本次开启都不会联网；开启后，下次窗口显示并加载设置后延迟 5 秒尝试，距上次实际尝试至少 24 小时，持续打开也不轮询。
- 默认跟随构建渠道，也可以显式选择稳定版或含预览版。“稍后”会暂停该版本 24 小时；“跳过”只抑制该版本，都不会回退推荐更旧的版本。手动检查忽略这些提醒规则，但仍遵守节流与限流。
- 使用匿名 GET 请求固定仓库 `kongerly/TalosDesk` 的 GitHub Releases 列表，不使用 `/latest`，不发送用户数据、登录令牌或 Cookie。请求采用系统代理、正常 TLS、固定产品标识和 API 版本头。
- 同源 HTTPS 分页每页 100 条、最多 5 页，总预算 15 秒，解压正文累计最多 5 MiB。重定向、循环、异常分页和不完整结果都会被拒绝，也不会据部分列表声称没有更新。
- 首次请求之间至少 60 秒。遇到 403/429 时遵守 `Retry-After` 和有效重置时间的最晚期限；没有有效头时至少等 60 秒，不自动重试。普通频率使用单调时钟，未来的缓存时间不会无限延后检查。
- 只有用户点击时，才通过浏览器打开 HTTPS `github.com/kongerly/TalosDesk/releases/tag/<合法标签>`。读取缓存和打开前都会精确校验主机、端口和单路径段，拒绝额外参数、片段或用户信息；不下载附件，也不渲染正文。

偏好和缓存按工作区隔离，各自使用 schema 1，不进入工作区导入导出。ETag 绑定完整请求和页内容，304 只复用有效匹配的缓存；整组分页完整成功后才替换旧结果。失败时保留带原时间的历史结果，更新尝试与限流记录，不能显示为新结果。

两个文件分别原子保存。写入失败不会抹去有效的网络结果，本会话的偏好和限流仍然生效。偏好损坏时保留文件、关闭自动检查并禁止直接覆盖，用户手动按“跟随当前渠道”检查；缓存损坏则只放弃缓存。删除后的恢复方式见[隐私说明](privacy.md)。

同一实例只保留一个检查任务。手动检查可以接管自动请求；关闭自动不会取消手动归属的请求。切换渠道会取消旧请求并使回调失效；确认退出会取消全部请求且不等待网络。错误只显示固定类别，不保存原始响应或底层异常。更新不接管命令，也不阻塞运行和输出。

## 诊断与桌面生命周期

本地诊断按工作区默认开启，可以关闭。它只保存版本、平台、异常类型、错误码和无源码路径的结构化堆栈。单条记录最多 8 个异常节点、4 层、每节点 32 帧、字符串 256 字符、64 KiB；总上限为 100 条、5 MiB、30 天。应用不递归、不跟随重解析点；损坏记录不展示原文，但仍计入清理。

致命异常没有等待重入保护，应用尽力记录一次后以非零码退出；未观察的任务异常每个会话最多记录一次，不改变运行时策略。失败时不换目录、不递归记录；强制结束、断电或严重资源故障不保证留下记录。磁盘时间使用 UTC，界面按 Windows 本地时区显示，不自动上传。

提示窗口由 WPF 统一提供，正文可滚动复制，确认默认取消/返回，Esc 和关闭都走取消，文件选择仍用原生窗口。主窗口正常退出时保存独立的窗口状态；缺屏或 DPI 变化会把位置限制在可见区域，损坏时回退默认布局。窄窗口允许滚动、换行和输出命令下拉选择，底部确认按钮保持可达。

托盘注册成功后，最小化才隐藏任务栏入口，命令和日志继续运行；恢复时保留普通/最大化状态。注册失败则保留任务栏，通知区域重建后尝试重新注册，失败时恢复窗口。托盘退出与“×”共用退出流程，关闭期间阻止重入；正常退出会释放托盘资源，不保存隐藏状态。
